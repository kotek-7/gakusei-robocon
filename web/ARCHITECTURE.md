# Webアプリの構成

React、TypeScript、Vite、Three.js、IndexedDBを使うブラウザー内の作業ツール。競技モデルは純粋なTypeScriptのまま維持し、UI、計算の実行、保存、3D描画を分ける。

## 境界と依存方向

以下の矢印はコードの依存を示す。

```text
study/App（組み立て）
  ├─ notebook → study/state → engine
  ├─ comparison → execution/identity → engine
  ├─ strategy / conditions → study/state → engine
  ├─ execution → study/match → engine
  └─ replay → viewport → engine
```

- `engine`：競技ルール、遷移、採点、方策、描画用フレーム。React、IndexedDB、Workerに依存しない。
- `study/state`：ノートv2の型と検証、v1読込、条件の選択。`study/match`が一試合の得点・イベント・フレームを一緒に生成する。
- `notebook`：ノートの読込・保存、50操作の履歴、ファイル操作。確定した入力を一操作として扱う。
- `execution`：入力の識別、キュー、Worker接続、結果の読込。`RunQueue`は実行・保存・通知の小さな契約を受け取り、Reactなしで検証できる。
- `study/persistence`：IndexedDBの具体実装。結果の要約とフレームを別ストアへ保存する。
- `comparison`：比較表、表示指標、基準、実行対象の選択。検索結果と実行対象を分離する。
- `strategy` / `conditions`：各編集機能のルール・入力部品・スタイル・テスト。機体条件の値を既存エンジン形式へ変換する処理はconditionsが所有する。
- `replay`：時間操作、対象と履歴の対応、状態表示、得点推移、場面メモ。時間・対象・視点を別々に保持する。
- `viewport`：Three.jsの描画と操作。意味対象IDとメッシュを対応付け、フレームから描く。再計算やノート保存は行わない。
- `ui`：メニュー、ダウンロード、表示設定。競技の判断処理を置かない。

機能専用のUI・ヘルパー・スタイル・テストは同じディレクトリへ置く。Appには機能間の接続と選択コンテキストだけを残す。新しい解析操作はreplay、新しいカメラ操作はviewportへ追加する。汎用イベントバスや巨大な共通ストアは使わない。

## 状態の所有者

| 状態 | 正本 |
|---|---|
| 作戦・相手・条件セット・メモ | notebookの文書履歴 |
| 選択中の作戦・相手・優先側・基準作戦 | App |
| 実行待ち・実行中・完了・失敗 | RunQueue |
| 完了得点 | IndexedDBのsummaries。画面には要約を保持 |
| 再生フレーム | IndexedDBのmatches。選択試合と基準試合だけ読込 |
| 再生時刻・区間・選択対象・詳細表示 | replay |
| カメラ・追従・補助表示 | viewport。比較時はreplayがカメラを共有 |
| 密度・既定速度・パネル幅 | ui/preferences |

派生した得点曲線や履歴の絞り込みは二重保存しない。カメラ履歴と文書の取り消しは別々に扱う。計算中は条件と作戦を固定し、閲覧と場面メモは使える。

## 保存と計算

ノートv2はlocalStorage、実行スナップショット・得点・再生結果はIndexedDBに保存する。ファイルには条件セットと作戦、場面メモを含み、再生結果は含めない。v1は一つの条件セットへ変換して読み込む。旧キーと旧DBを削除しない。旧結果の移行は、その結果と一緒に保存された入力を検証して行う。

項目の復元に使う機体条件は独立したスナップショットとして保存する。編集中の条件を変えても復元先は変わらず、「基準にする」を実行したときに更新する。

結果のキーはエンジン版、実際に選択された条件値、方策の内容、競合優先側から作る。名前、ID、メモ、使わない時間プロファイルは含めない。入力の意味が同じなら、複製や名前変更でも結果を再利用できる。

Workerには一試合分の入力スナップショットを渡す。一件の失敗は残りを止めない。中断時はWorkerを破棄し、未完了ジョブを待機へ戻す。世代番号で中断後の遅い応答を無視する。再読込時は自動実行せず、明示的な再開操作を待つ。

## 検証

`npm test`はモデル参照遷移、130試合の得点・イベント時刻、保存移行、結果の同一性、キューの失敗・中断、編集と解析の規則を検証する。`npm run build`は型検査と配信物生成を行う。UIはブラウザーで比較から再生、編集、復元まで確認する。フィールド原典は`../rulebook/field-2027.step`。
