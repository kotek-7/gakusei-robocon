# STRATA — ABU 2027

作戦を選び、ロボットの動き・得点・在庫を同じ時間軸で確認するシミュレーターです。441案のカタログを一括計算し、性能や相手の作戦を変えて比較できます。

## 起動

Node.js 22以上を使用します。

```sh
npm ci
npm run build
npm run dev
```

[ローカル画面](http://localhost:4173)を開きます。ソースを編集した後は `npm run build` で再ビルドしてください。

## 操作

1. 作戦一覧から選ぶと、同じ画面の3D表示が切り替わり、0秒から自動再生します。一覧は20案ずつ表示します。
2. 検索と「すべての狙い」で絞り込めます。方式・工数上限・並べ替えは「絞り込み・並べ替え」を開きます。「一覧で表示」は条件を解除し、表示中の作戦へ戻ります。
3. 相手・性能は「実行条件」で変更します。タイムラインやイベントを選ぶと、その時刻へ移動します。スマホでは3Dと再生操作を上部に固定し、一覧をスクロールできます。
4. 「工数・得点を分析」で補助の分析画面を開き、「全案を計算」で散布図と得点を確認できます。最大3案を比較に追加できます。作戦を選ぶと一覧と3Dへ戻ります。
5. 「比較の基準にする」で現在の実行を保存し、作戦や性能を変えます。得点差は同じ時刻の赤チーム同士を比べた値です。

「効率候補」は工数が同等以下・得点が同等以上で、どちらかが優れる計算済みの案がない候補です。得点順は赤の最終得点であり勝率ではありません。

「全案を計算」は検索・絞り込みに関係なく441案を実行します。各行の最終得点は赤：青の順です。「結果を保存」で作戦、性能、イベント、最終得点をJSONに保存できます。

工数は設計・製作・調整の人日を仮置きした加算モデルです。実測や納期の予測ではありません。「工数の仮見積もりを編集」からチームの値に変更でき、ブラウザに保存します。同じ技術は重複加算しません。反転はモードと終盤方針の両方から判定し、上段・共有域への対応を見込みます。指定外への代替建設による実際の対応範囲は別途確認が必要です。結果JSONには編集した見積もりと比較候補も含まれます。

## 計算範囲

建設場所の優先順、建設方式、奉納の有無、搬送優先度、終盤方針を組み合わせます。指定場所に空きや資源がない場合は、代替建設や待機を行います。

動作時間と資源を比較する簡略モデルです。CADに合わせた経路と操作位置を使用します。機体同士の衝突、転倒、通信、腕の到達範囲は判定しません。表示された動きの実機での成立や競技規則への適合は別途確認が必要です。計算条件の詳細は画面の「使い方・計算条件」を参照してください。

## 開発

`npm test` で資源保存・積載上限・再現性・再生・比較・探索中断を確認します。構成と変更先は[構成ガイド](ARCHITECTURE.md)を参照してください。

## CADと検証

フィールドは `../rulebook/field-2027.step` の形状と面色を使用します。変更時は `npm run import:field` で再変換してからビルドします。変換器は開発時だけ使用し、ブラウザへWASMを配信しません。

`npm run validate:catalog` は441案×相手3案×競合優先順2通りを再計算し、`../results/web-cad/catalog.json` に保存します。旧Python版の108方策とは別のモデルです。モデル版、入力条件、勝敗のタイブレーク順位は画面から保存したJSONにも含まれます。

[レビュー記録](../docs/review-2026-10-12.md)に出典、CADと公称寸法の差、修正内容、未実装の物理・裁定を記載しています。
