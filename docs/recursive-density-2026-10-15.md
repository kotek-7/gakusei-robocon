# 全領域の機能拡充と再巡回

専用ブランチ `codex/recursive-tool-density` で、既存8ワークスペースを起点に親1・領域担当3で実施。追加内容の全量を先に固定せず、各担当が実装後の操作から次の不足を選んだ。共有基盤とコミットは親が管理した。mainへの統合・pushは行っていない。

## ルール・目的の確認

アプリの目的は、機体能力と数値スペックの違いによる作戦・得点を調べ、共通の相手条件で比較し、経路を確認して設計判断を残すこと。現行のREADME・ARCHITECTURE・modelとルールPDFを照合した。

- ルールブック3.2、4.3：TRはGNDと受け渡しエリア、BRは受け渡しエリアとL1/L2。4.3.2のBRスロープ利用などの解釈は既存の仮定設定を維持。
- 3.4–3.6、4.4–4.5：TR最大3個・BR最大2個。アース2段とスカイ1段、上面色による支配、完成タワー2本以上（共有区域を含む）とムスティカ取得を確認。
- 4.2、4.6、8章：180秒終了時の状態で採点。ムスティカ設置後も続行。搬送5点、L1アース10/20・スカイ40点、L2は各2倍、ムスティカ250点。`engine/model.ts` の採点と照合。
- PDF12ページの図を画像で確認し、GND、受け渡し、L1、L2、共有区域の関係を再確認。ルール上の位置関係と有限グラフの移動モデルを混同しない。
- 2026-10-15に[公式News](https://aburobocon2027.id/news/)を確認。10月6日の重量訂正は合計60kg、ルールブックV1.1更新予告あり。[FAQ](https://aburobocon2027.id/technical/)はTo Be Confirmed。今回の確認は既存ローカルPDFが最新であるとの再認定ではない。
- 接触力学、転倒、把持軌道、通信なしの実行可能性は今回もモデル外。途中探索を網羅・最適性・実大会の勝率として表示しない。

## 巡回結果

| 領域 | 第1巡で追加 | 再操作後の第2巡 |
|---|---|---|
| 全体・共通操作 | コマンド分類と固定、履歴整理 | 固定操作バーと文脈別の有効状態 |
| 条件 | 編集開始時からの全体差分 | 項目/表示範囲の復元、取り消し、JSON出力 |
| 探索・計算 | 構成別の未探索・比較待ちの整理 | 絞り込み、並び替え、該当候補への移動、証拠出力 |
| 評価 | 比較する探索の条件差分 | 比較前提だけの抽出と差分出力 |
| 試合・区間解析 | 動作種別の時間内訳 | 機体/動作で絞り、個々の動作の時刻・区間へ移動 |
| 比較 | 同じ区間の得点増減・待機時間 | 区間端への移動と経路範囲外の非表示 |
| 状態グラフ・プロパティ | ページ移動の共通操作、直前局面との差分 | 未展開/得点あり抽出、変更属性だけの表示とJSON出力 |

| 3D・得点・履歴 | 既存の共通時刻・選択との連携を確認 | 建設履歴から次の変化までを解析区間として指定 |
