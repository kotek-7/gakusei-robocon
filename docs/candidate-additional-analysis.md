# 候補を起点にした追加探索・解析

## できる仕事

候補一覧の「この候補を追加探索」から、対象の赤固定手順を保ったまま青の展開を探索する。既知の相手手順の検査は別モード。10秒〜24時間の制限時間を指定し、保存停止・続行する。新しい赤候補の探索や他候補の検査には時間を割り当てない。新しい青手順は同じ構成の共有辞書へ登録する。

「探索履歴」では実行ごとの追加展開、最小点差の変化、検査済み手順数を確認する。同じ種類・制限時間で続行し、追加された展開のみを再生・解析できる。JSON出力は構成・設定・探索範囲・実行記録・追加証拠を含む。単独で復元できるバックアップではない。

「相手展開」では相手手順ごとの点差幅・赤得点の増減・実行不可を集計し、全ての記録済み経路へ進む。「手順の弱点」では赤の機体・指示番号・不成立理由ごとに集計し、その指示が不成立になった全展開を調べる。展開から既存の得点解析・実行不可・3Dの時刻へ接続する。

## 配置と根拠

候補が操作対象なので入口を候補Inspectorと作戦詳細に置く。追加探索、履歴、相手展開、手順の弱点は一つずつ独立した内容として切替する。計算の種類・制限時間・実行・停止は同じ操作列、結果の集計は表、補足は既存の?を使う。3Dとタイムラインは既存の隣接領域を維持。候補別の計算完了通知はその候補の履歴へ戻す。全体の「計算と進捗」からも実行対象に戻れる。

参照PDF `professional_high_density_ui_patterns.pdf` の長時間処理のbackground job、74 Detail drawer / split detail、75 Timelineに対応する。既存の選択と解析の連携を使い、説明文・折り畳み・メモ欄を増やさない。

OSS根拠はVS Code 1.95.3 `src/vs/workbench/contrib/testing/browser/testExplorerActions.ts` の `ExecuteSelectedAction.runInView`（選択スコープを実行要求へ渡す）、`CancelTestRunAction`（run/task対象を指定して停止）、`ReRunFailedTests`（結果を起点に再実行）。ソースを確認し、[公式Testing画面資料](https://code.visualstudio.com/docs/debugtest/testing)も参照した。実機のVS Codeは操作していない。本アプリでは「失敗テスト」をコピーせず、元の候補・構成を保持する対象指定と履歴からの続行に適用した。

## 実操作と保存の確認

作業ツリー7e41のVite5187を起動し、そのプロセスのcwdを確認。既存の終盤探索と、0〜180秒の検証用探索で操作した。

- 追加探索の入口は候補選択後1操作。従来は全体探索しか実行できなかったため、同等タスクの所要時間改善率は計測していない。
- 候補1件の状態で対抗手探索10秒をUIから実行。候補数を保ち、相手展開0→2件、最小点差未検査→−410。続いて既知手順の検査0→2件が完了し、重複する経路を追加しないことを確認。
- 保存して停止がcancelled履歴を残す。checkpoint後の再読込でinterrupted履歴を残し、mode・60秒設定・対象候補・未処理分岐を復元。
- 履歴から同じ条件で続行し、進捗ビューへ移動。JSONを実際にダウンロードし、対象・設定・範囲・追加証拠をreadback。
- 相手の最小点差から得点解析へ、弱点指示から3件の該当展開へ、さらに不成立時刻32秒等の診断へ移動。
- 3Dへフォーカス後も、追加探索ボタンを直接押せることを確認。表示中の対象照合とバックエンドの停止対象照合を併用。
- 1440px/390px表示。390pxの詳細領域clientWidth/scrollWidthとも382px。独立画像レビューはship。スクリーンショットは`.playwright-mcp/focused-*`（git対象外）。

## 残る範囲

機体速度・能力を変える感度分析、固定手順を部分編集する近傍探索は未実装。元の条件と派生条件を分けて結果の由来を保存する契約が必要。今回の対象指定探索は元の構成と固定指示に限る。確認済みの点差幅は勝率・全相手に対する保証ではない。実行履歴の長期保存は行うが、大規模な履歴の圧縮や複数候補の一括予約は未実装。
