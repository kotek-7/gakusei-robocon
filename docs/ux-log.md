# 全体レビューの記録

## 2026-10-14 改修前（codex 実装前の main）

Playwright で、条件作成 → 候補探索10秒 → 経路を開く → グラフ・3D → 評価 の順に操作した。

- 文書のように縦へ長いページだった。3Dは右の細い列に290pxで置かれ、試合を見る道具として小さかった。
- 選択局面（180秒）と3Dの表示時刻（0秒）が食い違っていても、画面上で区別しにくかった。
- 再生は2倍速固定で、コマ送り、イベント単位の移動、ループ、範囲指定がなかった。
- 候補の「得点と経路」は表の中の details で開く作りで、比較・ピン留め・再生への導線が弱かった。
- ショートカット、右クリックメニュー、設定、表示状態の保存、リンクはなかった。
- 説明文が多い（「〜できます」「〜です」）。

## 2026-10-14 基盤改修後

同じ流れを新しい作業台で操作した。

- 試合解析ワークスペースでは、中央に3D、下にタイムライン、右に得点とプロパティが同時に並ぶ。経路を開くとすべてが同期する。
- 未解決のまま残っている課題は次のとおり。
  - プロパティは選択局面（経路の末尾）を表示し、3Dと得点は再生位置を表示する。この2つの時刻の違いが、見ただけでは分かりにくい。
  - 動作履歴の表は、幅が狭い列で折り返しが多い。
  - 状態グラフ、作戦候補、評価、条件は旧UIを移しただけで、ヘッダー、右クリック、ショートカットがまだない。
  - ステータスバーの「選択」が内部参照のまま表示されていた（修正済み）。

## 2026-10-14 機能別の再帰レビュー・第1周

Claudeブランチ `claude/ecstatic-lovelace-h7ijyx` の `f744f84` から継続。外枠の次に、3D・再生・解析を並列にレビューし、候補比較を全体タスクとして確認した。

### 通した操作

- 条件作成→候補探索→相手待機の経路を開く→設置イベントに絞る→56秒へ移動。3D・タイムライン・得点が同期する。
- 再生30秒と選択局面180秒を照合。得点0対0と末尾310対0、取得条件未成立と末尾174秒を区別できる。
- 候補の相手待機経路をA、相手対応経路をBへ直接設定。末尾点差310 / -255、B−A=-565。再読み込み後も経路・ラベル・数値を復元した。異なる相手条件の2経路であり、候補の優劣を断定する比較ではない。
- グラフのページ送り、選択局面への戻り、N2のEnter選択による5秒への同期を確認。
- 条件の終了時刻180→120の編集がタブ移動後も残る。F6評価で計算完了後も「発見済みの範囲」「保証未確定」を保持する。

### 横断的な修正

- 比較A登録時に共通の選択経路もAに合わせ、タイムラインが空になる状態を解消。比較B登録は選択経路を変えない。
- A/B保存とマーカー・視点保存の競合を防ぐため、探索ごとの書き込みを直列化。復元が新しい編集を上書きしない。
- 評価の正常終了を時間切れと通知していた原因を修正。計算完了と探索の網羅性は区別する。
- 探索範囲の詳細を候補一覧直下へ移動し、失敗応答の有無によらず参照できる。

### 見た目と記録

既存のドック、表、ツールバーを維持。説明カードや装飾を追加せず、現在と末尾の時刻・値を明示した。機能別lintは0 FAIL。全体lintで残るhairline・shadow・outlined-boxは、作業台レビュー手順が許容する表・ツールバー・メニュー等の境界と影に該当する。

機能ツリーの7ルートの記録先を揃えた。`docs/feature-tree.md` を入口として追加し、レビュー手順の古い参照先を修正した。

### 次の優先度判断

今回の4機能群の子ノードは、対象タスクを再操作して飽和または優先度下位として記録した。アプリ全体が飽和したとは判断していない。

- 状態グラフの局所表示、ページ移動の共通コマンド化：未着手。既存操作は完遂できるため、今回の表示の正確性と保存より優先度下位。
- 独立したA/Bタイムライン：共通の再生元管理を設計する周へ延期。
- 狭いパネルのヘッダー折り返し・モバイル用配置：未着手。今回の確認は1440pxのデスクトップ作業台と255pxの解析パネル。スマートフォン全体の操作は未検証。
- 実機性能の妥当性、全戦略の網羅性、長時間探索の安定性：今回のUIレビュー対象外。
