# 条件付き作戦の探索と比較

候補探索は、主要な作戦仮説の比較と、細かな行動の探索を並行して進める。作戦仮説は目標地点・得点源・切替条件を保存し、各対戦の現在の盤面から行動を選び直す。

## 候補と探索予算

最初の比較対象は10系統・順序違いを含む13案。自陣確保、アース先行、共有部と自陣の組合せ、L2建設、ムスティカ、建設と反転の併用、反転主体、終盤反転、スカイ先行、搬送主体を含む。比較相手は自陣・L2とムスティカ・反転・アース先行・スカイ先行の5種類。相手も条件付きで行動する。

計算ステップの4回中3回を、この有限の比較に優先配分する。残る計算枠で従来の合法行動探索と対抗手探索を進める。行動探索・対抗手の建設順、反転、ムスティカを条件付きの仮説へ変換し、最大8案を追加できる。相手側から得た目標地点は陣地を対応付けて自分側で再検証する。既知のテンプレートだけに候補を限定しないが、この変換も限定された仮説生成であり、未知のあらゆる作戦を発見する保証はない。

13案の比較完了と、追加仮説・行動探索の完了は別に扱う。比較画面の最小点差には、対応する全裁定分岐の計算が終了した共通相手だけを使う。候補追加によって13案の比較完了が取り消されることはない。最小点差は、この相手集合とモデルに限った観測結果であり、実勝率や全相手への保証ではない。

## 判断と実行

- 建設済み・資材不足・移動不可の目標を飛ばし、次の目標を検討する。
- 反転を使う作戦では、空荷のBRが利用可能な相手塔を見つけると反転を選ぶ。
- ムスティカを使う作戦では、取得権が成立すると設置目標へ切り替える。到達と設置の最低限の時間が残らない場合は候補から外す。この判定は完全な配送所要時間の証明ではない。
- 建設が終わると搬送で加点する。搬送対象の資材がなくなると次の種類を選ぶ。
- 待機中は1秒刻みで条件を再評価する。実行中の操作は完了まで保持する。
- 条件付き作戦の物流は床経由。直接受け渡しや混載の詳細な組合せは行動探索で検証する。条件付き作戦間の得点だけで直接受け渡し機構の価値を判断しない。

## 固定手順の再現性

行動探索で見つかった固定手順の待機は、探索時に実際に待機した区間の終端時刻を保存する。別対戦のイベント回数で手順を進めない。直接受け渡しで相手の準備が整っていない場合は、その受け渡しだけを待たせ、もう一方の独立した移動を止めない。

560点の直接受け渡し経路について、相手TRの空荷往復0・1・3・6回で、自分の得点・動作列・動作時刻が一致する回帰テストがある。条件付き作戦にも、無関係な相手動作を追加した場合の時刻までの一致を検証する。

待機の再現方式が異なる旧候補探索は続行できない。保存済み結果の閲覧と書き出しは維持し、同じ構成で新しい探索を作成する。新方式の候補・判断状態・未計算分岐は従来通りIndexedDBとバックアップへ保存される。

## 実用性の範囲

画面には作戦名、切替条件、必要機構の目安、相手ごとの得点、再生経路を示す。物流・リトライも経路分類に含め、搬送だけの経路を何もしない経路と区別する。

必要機構は設計の目安であり、機体構成の自動最適化ではない。TR/BR別の性能入力、重量・工数・実機成功率、接触・床の収容密度、通信禁止下での認識と分散制御は引き続き別途検証が必要。全盤面を利用するモデル上の判断を、そのまま実機で実装可能とみなさない。

## 検証

`web` ディレクトリで実行する。

```sh
npm test
npm run build
node --import tsx scripts/policy-check.ts
```

`policy-check.ts` は赤の移動速度0.8m/s・他は標準の構成で、13案×5相手の比較完了まで最大30,000ステップ実行し、集計を `results/policy-comparison-2026-10-14.json` に保存する。計算時間は実行環境に依存する。既存のルール参照129遷移、合法性、再生、保存再開のテストも維持する。
