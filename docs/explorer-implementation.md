# 状態遷移エクスプローラの実装・検証

旧カタログ、Web独自シミュレータ、Pythonマクロモデルと旧生成結果を撤去。競技資料・CAD・描画部品を保持し、モデル、保存探索、API、Web表示に分離した。

- Pythonの有限操作モデルが合法行動・同時遷移・得点を計算する。
- SQLiteに全エッジ、合流局面、展開カーソルを保存。ローカル計算スレッドはブラウザから独立して動く。
- Webは条件表、状態グラフ、選択局面、保存経路の3D、固定分類階層、構成比較を表示する。
- 未探索・集計未完了・短い時間窓の評価を区別する。

## 検証した範囲

Pythonの回帰テストで小局面の素朴な全列挙との一致、再開前後の同一グラフ、同時選択の混合方針、リトライ・競合・受渡し・得点・待機同値経路の重複排除を検証。Webは型検査とproductionビルド、CAD寸法・ハッシュを検証。

ブラウザで赤走行3段階の独立構成生成と1秒窓の完全探索・評価、分類階層、終盤局面の手動分岐、反転による85:85から125:45への得点変化、同じ経路の3D再生、停止とリロード後の件数維持を確認。1440pxと390pxで表示を確認。

180秒の全構成の全探索完了は検証していない。モデルの有限化・未収録の物理条件は [model.md](model.md) に記載。実機上の実現性や実大会の勝率を保証するものではない。


## 候補探索の終了と追加計算の判断

候補探索の `scopeComplete` は、全構成の目標順序の探索待ちと、生成済み候補の相手対応待ちがともに空になった場合だけ成立する。詳細な全探索の `complete` とは別であり、最適性を保証しない。従来の候補レポートの `complete: false` は保持する。旧保存データも待ち行列から判定でき、スキーマ移行は不要。

時間切れ・手動停止・対象範囲の探索済みを表示する。探索済みの場合は追加実行を無効にする。候補数・作戦分類数・発見済みの探索待ち・相手対応の未検証数を表示するが、総候補数、全体の進捗率、完了予定時刻は推定しない。

1回の時間は5分を既定とし、10秒〜24時間から選択できる。長時間の計算も停止・再開でき、時間制限は探索の十分性を示さない。各実行の候補増加、分類増加、相手対応の検査数、同じ構成での相手待機時の最高得点更新を直近12回分保存する。初めて候補が出た構成は得点更新に含めない。旧保存データの実行履歴は復元しない。直近3回の時間切れ実行で分類も最高得点も増えず、生成済みの相手対応待ちもない場合は、候補の経路を確認する目安を表示する。自動打ち切りや収束保証ではない。

## 評価計算の進捗

評価は読み込み、試合展開集計、作戦別集計、完全探索済みの構成の保証値計算、保存の各段階を通知する。段階内の処理済み局面数または作戦数と、その段階の総数をプログレスに使用する。読み込み・保存は件数不明の表示とする。構成の処理済み件数と経過時間を併記し、全体の残り時間は算出しない。

進捗はSQLiteへ最大およそ毎秒4回と段階・構成の変更時に保存する。評価結果は最後まで計算できた場合だけ置き換える。停止時は中断、プロセス再起動時は実行が途切れた状態として記録し、再実行は最初から計算する。計算の完了と、未探索分岐や履歴上限を含む評価の網羅性は区別する。
