# ブラウザ版の実装と検証

React / Three.jsの画面を維持し、計算をTypeScriptのWeb Worker、保存をIndexedDB、線形計画をHiGHS WebAssemblyへ置き換えた。Pythonサーバー・SQLite・SciPyの起動は不要。旧実装と解析済みデータの互換処理は持たない。

## 自動検証

`cd web && npm test` で次を検証する。

- 旧実装 `8a3f0dd` から採取した129遷移について、合法行動、裁定分岐、遷移前後の局面、得点、描画フレームを照合。フレームの浮動小数は1e-9で比較。
- 小さな時間窓での独立した再帰列挙と、保存グラフの全局面・エッジ数が一致。分割実行と保存・再読込み後の実行も同じグラフになる。
- 候補探索で1個搬送、直接受け渡し、混載、建設中の先行搬送を検証。固定した手順が実行不能になった場合は別作戦へ差し替えない。
- 候補のカーソル、移動先への継続、入出辺、相手探索・共通比較ジョブが保存・再開後に残る。
- HiGHS Wasmで混合同時行動ゲームと、勝利確率の下限を維持する点差最適化を検証。ソルバー未完了の結果を保証値として採用しない。
- 完全探索前の評価は保証なし、完全探索後のみ保証あり。履歴を重複排除し、中断時には以前の確定評価を残す。
- IndexedDBの保存・復旧、ブラウザ版バックアップの復元、不正ファイルの拒否、停止・再開を検証。
- 提供CAD資産のハッシュと寸法を確認。

型検査は `npm run typecheck`、静的配信ビルドは `npm run build`。テストの参照データは圧縮JSONで、製品には同梱しない。

## 実ブラウザで確認した操作

計算APIのないVite previewからproductionビルドを開き、以下を確認した。

- 2秒窓の探索を作成し、全探索を完了。17局面・31遷移を保存し、Wasmで評価。勝利確率の保証範囲は0〜100%、点差下限は0。
- バックアップを書出し、同じファイルを新しい探索として復元。再読み込み後も17局面・31遷移と評価を保持。
- 180秒のモデルで候補探索。探索中のタブ切替、再読み込みからの復旧、手動停止・再開、候補の経路の3D表示を確認。確認時点で9候補、相手待機時の最高点310点。これは有限モデルの発見結果であり最適値ではない。
- 390px幅でページ全体の横はみ出しがないことを確認。
- 別タブで開くと書込み所有権の競合を表示し、二重実行を防ぐ。
- `/robocon/` サブディレクトリで静的配信し、探索・Wasm評価まで完了。ネットワーク要求は同一サイトの静的資産だけで、API要求は発生しない。

## 保存と進捗

探索状態と一覧用サマリーをIndexedDBの同一トランザクションで確定する。探索中はおおむね1秒間隔と終了時に保存。保存前の直近の処理はタブ終了で失われる場合がある。起動時にrunning/evaluatingを中断状態にし、自動では計算を再開しない。

候補探索の `scopeComplete` は限定した経路・待機時刻の全構成で、候補・相手探索・共有比較ジョブが全て完了した場合だけ成立する。詳細全探索の `complete` と区別する。時間上限、手動停止、容量・状態数上限を完了扱いしない。

評価は読み込み、履歴、統計、保証計算、保存の段階を表示する。評価結果は全工程を終えてから置き換え、中断時には再計算する。履歴上限は30,000件で、上限到達時は統計未完了を明示する。

180秒の全構成・全分岐の完了や、長時間のスリープをまたぐ実行は確認していない。接触力学・転倒・把持軌道などのモデル外条件は[モデル仕様](model.md)を参照。
