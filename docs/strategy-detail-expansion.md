# 作戦詳細の拡充

## 既存機能のレビュー

候補一覧から3Dへ適用し、試合解析の動作履歴、区間解析を実際に確認した。既存機能は動作の時刻、得点、機体別の稼働・待機、動作別内訳を持つ。一方、別ワークスペースへ移ると候補との対応が見えない。候補の `plan` は相手待機時の完了イベントを圧縮した概要であり、機体別の固定指示そのものではなかった。固定指示は保存されているが公開取得方法がなかった。

## 接続と配置

- 候補Inspectorの「作戦を詳しく見る」から、選択候補と選択展開を渡す。
- 詳細、3D、タイムラインを同一ワークスペースに配置。既存の一覧の選択とフィルタを保持して戻る。
- 固定指示、実行記録、得点の変化、実行不可、機体構成を扱う。作戦と展開を区別し、固定指示の数を完了回数にしない。
- 内容は「機体別の概要」「固定手順」「完了結果」「動作・時間」「得点」「実行不可」「機体構成」の7ビューに分け、タブで切り替える。一度に表示する本文は一つ。候補・展開の選択は共通とし、選択中のビューは保存する。3Dへの操作は非同期取得後も対象一致を検証する。
- 説明は既存Helpを使用。検討メモやdetails折り畳みは追加しない。

## 分担

- strategy_plan / plan_semantics: 固定指示と完了結果の意味、資材条件、機体構成。
- strategy_execution: 動作別時間、同時刻の他機体、期間と記録終了。
- strategy_instructions_api: 固定指示取得、欠落、コピー独立性、バックアップ復元。
- strategy_score: 開始点と増減、同時刻の動作、再生移動。
- strategy_identity_review: 構成/候補/展開の識別と非同期競合。
- strategy_comprehension_review: 初見での作戦理解。
- impeccable_finish_reviewer: 実画像とコードの独立レビュー。

各枝の巡数、根拠、未処理案は `docs/ui-reference/strategy-*.md` に記録。ソース・数値検証の巡とブラウザーの巡を区別する。

## 1ビュー1コンテンツへの整理

ページ内ジャンプをタブ切替に置き換え、概要・固定手順・完了結果も別々に表示する。「手順へ」は対象機体を選択した固定手順ビューへ移動する。左右キー・Home・Endで切替可能。既存の保存レイアウトでは概要から表示し、選択中のタブは再読込後も復元する。3Dとタイムラインの領域は維持する。

実ブラウザーで7ビューの単独表示、機体別手順への移動、キー操作、再読込、390px/1440px表示を確認。390pxで詳細領域のclientWidth/scrollWidthはともに382px。TypeScriptチェック・production build成功。
