# カタログの分類とデータ構造

この画面は、機体の対応範囲と行動方針を上位から選び、実行できる方策を絞るために使う。候補の横並び比較、差分評価、Pareto散布図は使用しない。

## 元のデータ

`catalog()` の441設定は、建設場所の優先順2項目、建設モード3種、奉納の有無、搬送方針3種、終盤方針3種の有限な組合せ。自陣のみを優先する一部の組合せは生成器が除外する。相手の応答や試合結果は設定の属性ではなく、方策と相手、性能、乱数、競合優先順を入力して得る結果である。

`mode=flip` または `end=flip` のとき、反転条件は常時になる。`mode=flip` の終盤指定は行動を変えない。建設先の並び替えに使うのは `mode=reuse` の真偽であり、build/flipの区別はここにはない。この条件式を正規化した297方策を選択対象とする。設定IDは `sourceIds` に保存する。得点一致や工数一致は方策同値とは扱わない。

## 階層と横断条件

分類は奉納の有無 → 反転条件（なし・120秒以降・常時）→ 土台優先の有無 → 最初の塔取得前後の優先エリア → 搬送方針。各階層の兄弟群は排他的で、子の和集合は親の作戦集合と一致する。展開状態は複数群を保持する。分類への絞り込みと展開は別操作であり、パンくずから親に戻れる。

活動範囲・登り方・工数上限は階層と独立した条件。すべての階層で即時に適用する。条件変更で分類が空になった場合は空の理由を表示し、分類を勝手に変更しない。L1限定はシミュレーションの代替建設・反転先も制限する。BRスロープはルール4.3.2との整合確認が必要な仮説。

## 得点と相手の分類

表示中の作戦について、現在の相手と競合優先順2通りで計算した得点分布を示す。初期表示から計算する。未計算値はゼロとして扱わない。工数と分類だけの変更では計算結果を再利用し、性能・相手・活動範囲・登り方が変わると再計算する。

作戦の詳細から相手297作戦×2通りを評価できる。相手は奉納・反転条件・土台利用で12群に分類する。得点が同じという理由だけでは同じ作戦にまとめない。

## 表示

左に工数と機体条件、中央に複数展開可能な階層カタログ、右に表示中の得点分布。各群に作戦数・工数幅・得点幅を示す。工数見積もりはローカル保存。結果JSONには分類・機体条件・工数・結果を保存する。

## 実装の所有者

Reactへの移行後は、分類・機体・工数条件を`catalog/Catalog.tsx`、集合の分割と絞り込みを`navigation.ts`、計算ジョブを`calculation.ts`が所有する。DOMから条件を復元しない。通信型は`protocol.ts`でWorkerと共有し、工数保存キーと結果JSONの形式を維持する。全体の採否は[技術選定](../web/ARCHITECTURE.md)を参照。
