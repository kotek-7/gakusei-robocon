# 操作領域の拡充

ルールブックと現行のブラウザ計算モデルを確認してから、条件・評価、探索・グラフ、試合解析を並行して使い、機能の追加後に子機能を再検討した。競技モデル、有限化の仮定、未完了探索の扱いは変えていない。

## 新しい作業領域

- **検討記録**：経路・時刻・範囲・選択対象とメモを保存。判断は未確認・採用候補・見送り。検索、抽出、A/B登録、コピー、削除取消を備える。
- **区間解析**：指定した区間の4台の動作時間・待機時間を比較し、最長待機へ移動。同じ範囲の得点増減やタイムラインと照合する。
- **検討・解析メニュー**：新しい領域と、その領域で使う操作をまとめる。
- **小画面の領域切替バー**：700px以下で1領域ずつ全幅表示。デスクトップの分割配置は保持する。

## 既存領域から掘り下げた操作

| 領域 | 最初の追加 | 再評価して追加した子機能 |
|---|---|---|
| 条件 | 構成数を増やす項目と固定後の構成数 | 値の直接固定、赤青差分、項目別コピー、表示項目だけ一括変更 |
| 候補 | 共通相手手順を指定した比較 | 未比較・実行不可で抽出、実行不可の時刻と理由、比較経路をA/B登録 |
| 状態グラフ | 選択局面の前後・経路だけを表示 | 未展開局面の巡回、ページ内件数、物体検索・種別抽出 |
| 試合解析 | 区間の動作・待機集計 | 最長待機への移動、区間得点差、選択機体・範囲の履歴CSV |
| 比較 | 得点・行動・機体稼働で抽出 | 項目検索、共通再生範囲の表示、範囲外の値を非表示 |
| 評価 | 構成・作戦の検索と並び替え | 未完了・未決・保証ありで抽出、分布詳細、表示結果JSON |
| 計算履歴 | 終了理由で抽出 | 抽出結果の集計・JSON保存、同じ時間制限で探索を継続 |

詳細な採否と参照したOSSのソースは [機能別の記録](feature-tree/README.md) に残した。参考対象はBlenderのタイムライン・Outliner・Spreadsheet、GodotのInspector・GraphEdit。見た目の模写ではなく、対象選択から詳細操作へ進む構造を参考にした。

モデル・前提は既存の検索と分類表示を維持。今回の判断作業に対して新たな説明パネルは増やしていない。3Dは保存済み状態の説明という用途を維持し、新しい検討・区間解析領域に配置した。

## 確認

- 1440pxと390pxの実画面で配置を確認。390pxのページ全体の横はみ出しは0。
- 実際に10秒の候補探索を行い、その保存経路を区間解析した。30〜90秒に赤TRの動作44秒・待機16秒、赤BRの動作54秒・待機6秒、赤の得点増155を表示。これは今回の条件・経路の動作確認であり、作戦性能の保証ではない。
- 条件の候補追加で構成数1→2、固定で2→1、取り消しで1→2になることを確認。
- 記録の見出し・メモ・判断を保存し、再読み込み後の値を確認。
- taste lintの指摘は既存の表・パネル境界、メニュー等の影とドラッグ位置表示。操作画面の用途に従い保持。impeccableの変更領域検出は指摘なし。日本語を短い操作名と状態表示に揃えた。
- PRODUCT.mdのRuntime節には旧構成の説明が残っている。現行の実装・README・docs/model.mdを根拠にした。
- `npm --prefix web test`：49件成功。領域表示の最終調整後に保存・遷移・レイアウトの関連7件を再検証して成功。
- `npm --prefix web run build`：型検査・ビルド成功。既存の大きいバンドルと静的/動的import重複の警告は残る。
- ブラウザから書き出したバックアップを読み、記録2件、30〜90秒の範囲、64遷移の保存経路、比較A/Bの経路を確認。
