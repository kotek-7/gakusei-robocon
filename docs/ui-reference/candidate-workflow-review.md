## 根拠と採用する構造

既存OSS調査 `candidate-controls-2026-10-15.md`、`candidate-matrix.md`、`candidate-recovery.md` を現在の条件と照合した。Godotの選択と起動の分離はcheckboxの比較集合と行の検査選択に合う。VS Code OpenEditorsの未保存対象への明示移動は、一覧外の作業対象へ復帰する今回の経路に合う。実機OSSをこの担当で操作したという主張はしない。新たな大枠UIや別の保存モデルはこの監査では実装しない。

A/Bの出典は比較列の既存ラベルへ追加し、別の履歴パネルを新設しない。ラベルの対象は選んだ実経路、意味は識別、使用場面は比較への移動・再訪。更新はA/B割当時、保存は既存workspace.ab.labelと同じ。裁定順は表示補助で、順序だけに識別を依存させない。

## 実操作の証拠と制約

MCPの独立newPageは既存プロファイル使用中で起動できなかったため、別headless Chromeを起動。`http://127.0.0.1:5187`、新規の終盤174秒の検証局面から実エンジンで5候補を生成した。親のタブ・既存保存データには触れない。1280×720で上記のネストEsc、検索0件、比較維持、対象復帰、checkboxのSpace操作、再読込を確認。スクリプトは `/tmp/candidate-workflow-browser.cjs`。

`comparisonLabel.test.ts` は同じ得点・終端局面でも異なる経路を区別するケース、同じ経路を再生成した際の安定性、裁定順の表示を検証し成功。指紋は有限長なので衝突不存在を保証しない。共有コンポーネントへの適用と修正後の統合実操作は親担当へ引き渡す。

今回の独立レビューは機能数の達成を完了条件にしない。再入場の空表示、ネストEsc、A/B出典を優先し、残る枝はmatrix→Inspectorへの明示引継ぎ、表の表示外選択への復帰、下書きの寿命へ具体化した。
