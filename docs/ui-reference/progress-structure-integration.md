# 計算と進捗の構造変更・統合確認

## 変更の境界

従来の見出し・説明・折り畳みを重ねた進捗表示を、実行単位、累計、履歴の行、構成別の表へ整理した。既存の計算・保存モデルは変更していない。

- 処理名、現在状態、停止を同じ実行ヘッダーに配置。時間予算または今回の行動組数をメーターの単位として表示。
- 評価は処理済み構成と現在構成の工程を親子関係にする。工程は構成ごとに繰り返すため、全体の達成順を示すステッパーは設けない。
- 保存状態と結果への移動を実行の下端へ配置。定期保存中は計算自体を終了扱いしない。
- 累計と履歴の増分を分離。最新3行を常設し、選択した回の得点差を開始前・終了時・差の列で示す。履歴の絞込・書出・同予算での続行を保持。
- 構成別結果は列で比較し、未着手構成を表末尾へ集約。
- 計算パネルが見えている間は上部の重複する計算操作を隠す。作戦候補へ戻すと上部操作も戻る。

既存の局面数・遷移数は計算途中の未保存分を含むため、見出しを「保存済みの探索範囲」から「探索範囲の集計」へ修正した。保存時刻・失敗は実行欄で確認する。

## 実操作

ローカル4187のこのチェックアウトをChrome/Playwrightで検証した。

- 新規探索を作成、候補探索を開始、停止、保存済みになるまで確認。
- 計算パネルでは上部実行操作が消え、作戦候補へ切り替えると戻ることを確認。
- 終盤174秒の局面から100行動組の全探索、評価、評価結果への移動を実行。
- 評価後の再読込で「前回の評価」を確認。
- 続けて候補探索を実行し、計算履歴の表示・JSON書出・再読込を確認。探索追加で無効になった旧評価が出ないことも確認。
- 履歴担当は実データに加え、別の合成5履歴で全件表示・得点更新の選択・終了理由の絞込を確認。

## 状態と幅の検証

実データへ表示用の状態を注入し、測定不能の工程、定期保存、最終保存、保存失敗、未着手構成の各表示を確認した。実際にディスク障害を起こした検証ではない。

- 分母不明は不定進捗。実測値のないパーセントを表示しない。
- 定期保存では「実行中」を維持。最終保存ではactive状態を維持し停止操作は無効。
- 保存失敗時の時刻は「前回保存」と表示。
- 全3構成中1構成着手の状態で「未着手 2構成」を確認。
- 1440/700/390pxで計算領域のclientWidthとscrollWidthが999/692/382pxで一致。表は内部スクロールし、ページ全体は横にはみ出さない。

## 検証結果と制限

全179テスト、型検査を含むproduction build、差分空白チェックが成功。Impeccable detectorを変更UIへ実行し指摘なし。既存の依存ライブラリー・chunk分割に関するビルド警告は残る。

検証ブラウザーではWebGLを無効化した。今回の対象である計算操作・進捗・履歴・保存表示を検証し、3D描画品質は対象外。変更前後の所要時間短縮率は測定していない。履歴が直近12件までという保存仕様や探索の網羅性は変更していない。
