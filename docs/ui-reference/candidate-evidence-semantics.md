# 候補証拠の意味：独立担当の再帰点検

2026-10-15。比較表・得点差分を担当。親のブラウザで統合実操作を確認する契約。ここでは計算・型検査を扱い、操作短縮は実測していない。

## 根拠と配置

ABU公式Rulebook v1.1の8（個別ブロック得点）と9（合計得点・同点判定）をローカルPDFから抽出し、`docs/model.md`、`engine/discovery.ts::record`、`evidence.ts`を照合。候補は固定した赤手順、相手IDは固定した青手順、各responseはそれを実行した裁定結果。`shared`と共通相手集合を両方確認した場合だけ、同構成の全裁定比較に用いる。点差0を勝敗引分けと表示しない。

既存のOSS根拠`candidate-matrix.md`（Godot 4.5-stable `scene/gui/tree.cpp::Tree::gui_input`、選択と起動の分離）を再利用する。今回も値セルで選択し、下部の実行で3D/A/Bへ渡す同じ状態契約に該当する。独立担当はGodot実機を操作していない。添付カタログの検索・絞込の器は既存比較表のselectを再利用し、単独ボタンや別ドックは追加しない。

## 第一巡：比較の意味から不足を発見

- 候補間の最小点差が同じなら「点差が異なる手順」に出ない。しかし一方の候補だけ裁定で上下する場合がある。
  - 採用：同一相手の全裁定について点差の振れを判定し、「裁定で点差が変わる手順」で絞込。候補間の開きと裁定内の変動を混ぜない。
  - 配置：比較表全体に作用する既存表示select。選択済み経路は絞込で勝手に置換しない。
- 相手待機から点差が落ちても、赤の得点を失ったとは限らない。青の得点が増えただけかもしれない。
  - 採用：選択展開の得点欄を`EvidenceScoreDelta`へ置換し、赤の増減・青の増減・点差の増減を並べる。
  - 配置：選択展開に従属する既存dl。独立カードや因果推測は追加しない。相手待機自身なら冗長な0差分を表示しない。

## 第二巡：追加結果をさらに分解

- 不可ありのフィルターは全裁定を見る一方、セルの警告は最小裁定だけを見ていた。選択した行が警告なしに見える場合があった。
  - 採用：セルは全裁定を集計し「赤/青に実行不可の展開」と明記。特定展開の不可件数と混同しない。
- 実行不可の当事者は赤とは限らない。青の不可を赤の実行性能の欠点と読める。
  - 採用：「赤に実行不可」「青に実行不可」の専用絞込。元の全体フィルターも残す。robot 0/1と2/3を分離し、非最小裁定も対象。
- 点差が同じでも両チーム得点や不可状況は違い得る。
  - 検証：同じ点差・異なる得点のテストを追加。点差フィルターの名前は「点差」のままにし、同一展開・同一勝敗とは呼ばない。
- 最小値という言葉は保証に見える。
  - 採用：表captionを「同じ相手手順・全裁定の最小点差」、一つの注記で未発見手順への保証でないことを示す。

## 続く枝と採否

- 点差の因果分解は不採用。得点の増減は観測差であり、相手干渉の寄与を確定する反実仮想の評価ではない。
- 完了記録の同一性は既存`firstRedDifference`を検査。青のみの同時組を除いて赤の順序と同時性を保持しており、同じ手順や同じ時刻と表示していないため変更不要。
- 完了組の「次の相違」ナビは将来案。最初の相違から原因を検査する現行フローを先に実操作で確認し、長い履歴を何度も往復する需要を確認して採用する。
- 共通相手ごとの勝率推定・裁定件数の確率化は不採用。探索の件数は発生確率ではない。

## 検証契約

`comparison.test.ts`で最小値が同じ場合の裁定差、相手手順欠損、青だけの不可、相手待機からの得点分解を検証。親へ比較select、非最小裁定の選択、3D/A/B対象一致の実操作を依頼。ファイルは保存状態を増やさず、既存の取り置き・選択状態に従う。
