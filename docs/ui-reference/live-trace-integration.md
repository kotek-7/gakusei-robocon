# ライブ探索表示の統合

「候補を見る」は保存情報の右に単独の下線リンクとして置かれていた。結果への移動をジョブ見出しの停止操作に隣接する共通ツールボタンへ移し、候補／評価／局面の短名とアイコンを表示する。集計表内の構成IDリンクは表の対象選択なので維持した。

ライブ表示は現在の計算のメーター直後に置く。評価は既存の件数・バーに工程の現在地を添える。3Dや通常のグラフ表示への選択は変更しない。

## 配信

`job.activity` は独立したZustandストアへ渡す。高頻度イベントから `upsertSearch` や `invalidate` を呼ばない。最大8探索の最後のスナップショットだけを保持し、探索削除時に除去する。IndexedDB、バックアップ、ワークスペースには保存しない。再読込後に過去のライブ記録は復元しない。

## 検証

2026-10-15、作業ツリーのVite（5187）で実探索を実行。

- 候補探索10秒で77イベントを受信。37種類の処理局面、最大48局面・46遷移、509展開を観測。これは一度の実行結果であり性能保証ではない。
- 約100msを目標に送信するが、単一展開・保存・メインスレッドの負荷で受信間隔は延びる。グラフが1.5秒以上更新されなければ「更新待ち」を表示する。
- 1000×800と小さなウィンドウで実画面を確認。実測幅へ座標を合わせ、目盛の文字サイズを保持する修正後に再確認。
- 再開時のstartingイベントが0件・0局面。停止後の受信件数122が350ms後も変わらず、最終記録を保持。
- 全探索80組の表示と処理数が一致し、全局面がexactのID。候補探索の履歴を混ぜない。
- 評価はcompleteの実イベントで「評価完了」。探索遷移は0件で、工程だけを表示。
- 見出しの「候補」ボタンから候補一覧へ移動。検証用探索は削除し、元の探索へ戻した。
- 全188テスト成功。実観測の有無で探索結果が一致する2件を含む。イベント待機のテストを固定時間から条件待機へ変更後、その4件を再確認。型検査・ビルド成功。

3担当（エンジン、表示、独立レビュー）、委譲1段。表示担当は4巡、独立担当は2巡で記号・終了状態・座標・観測の非干渉性を確認。親がイベント接続、結果移動、実ブラウザー検証を担当した。全体グラフの保存・履歴再生は今回のライブ表示の範囲に含めない。
