# 作戦詳細の選択と3Dの一致

## 対象

`strategy-detail/selection.ts`、`commands.ts`。候補一覧で選んだ作戦・相手・裁定経路を詳細画面と3Dで一致させる。新しいUI部品は追加しない。

## 観察と修正

- `goToNode` は非同期読込の完了時にsessionを書き換える。呼出側で完了後に選択を調べても、古い要求による書換えは防げない。詳細専用の移動では読込と反映を分け、要求世代・探索・session・ワークスペース・作戦選択をすべて確認してから反映する。
- 同じ終局nodeとpathでも相手ありの結果と相手待機を識別する。復元された選択が欠落している場合は相手待機へ自動的に置換しない。
- 経路は終局nodeとは別に照合する。裁定で分岐して合流した結果を混同しない。
- 「共通手順で最小点差」は探索中に別の結果へ変わり得る。読込中に結果が更新されたら古い結果の反映を止める。
- 場所・ロボット選択は経路反映後に行う。指定時刻は選択展開の終局までに制限する。

## 局所巡回

5つの観点で実装・テストを見直した。画面実操作の回数ではない。

1. 選択の識別：baselineと相手ありの同一経路衝突を修正。枝ごとの全経路を鍵に維持。
2. 復元：存在しない探索・構成・候補・展開を検証。欠落対象の自動置換を棄却。誤った作戦に見せないため。
3. 連続操作：非同期結果の適用を要求世代で制限。候補変更・別workspace移動後の結果を破棄。
4. 継続探索：意味指定のworstと個別経路指定を分け、読込中のworst更新を検出。
5. 領域連携：同じ経路の適用・時刻移動・場所選択を一つの操作にまとめ、JSONプロパティ順序に依存した選択比較を撤去。

## 検証と残る範囲

`selection.test.ts` の6テストが通過。画面での候補連続変更・探索変更・詳細と3Dの一致は統合担当の実操作対象。ローカルでは純粋関数とコード経路を確認した。既存の他editorのgoToNode全体の競合防止は対象外。新規UI操作・保存状態は追加していない。子担当への再委譲なし。今回の編集範囲の実装は完了し、画面上の連携確認を統合担当へ引き継ぐ。
