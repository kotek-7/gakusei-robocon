# 候補探索の累計と実行履歴

対象: `jobs/DiscoveryHistory.tsx`、`SearchProgress.tsx`、`discovery-history.css`。

## 使う仕事と配置

- 保存済みの累計を確認する。候補数・対抗手の検査・探索待ちを3列の定義リストにする。種類は候補、比較待ちは検査の補足値として従属させる。構成数は構成表が扱い、現在実行中の増分はCurrentJobが扱う。
- 各回の終了理由と増分を比較する。履歴は常時直近3行を同じ列で読む。全件表示と終了理由・更新有無の絞り込み、絞込JSONの書出しを同じテーブルの道具として置く。
- 得点更新を確認する。回番号または得点更新セルで選択した1回だけ、開始前・終了時・差を数値列で表示する。Modal内の箇条書きは使わない。
- 同じ予算で計算を続ける。選択回に所属する制限時間と再開ボタンを隣接配置する。過去時点への巻き戻しや、その回の候補スナップショット閲覧は実装に存在しないため示唆しない。

## 参照と採否

PDF `professional_high_density_ui_patterns.pdf` p69、Background job queue #86のName/Status/Actionの対応を、逐次実行履歴の回/終了/増分/選択後操作へ適用した。全行のカード化、全行に詳細の折り畳み、履歴を独立タブへ隠す案は採用しない。履歴は現在の計算結果を理解する隣接資料で、同時参照できる必要がある。

OSSの進捗面は `progress_patterns` 担当がVS Code 1.95.3、Blender 4.3を調査。履歴専用OSSの実操作は行っていない。本枝の履歴列構造の直接の参照はPDF実図。

## 巡回

1. 旧表示をコードと親の実画面で確認。details配下の履歴、段落で連結された合計、得点差のModalリストを取り除く。累計と今回の責務をlayout/live担当と調整。
2. 実装後の意味と密度を確認。構成カウンタをCoverageへ、未保証の注意を累計末尾1箇所へ集約。意味の異なる数値に同じラベル・単位を反復しない。
3. patterns担当の独立レビューで、得点更新セルから選択できない問題を発見。回番号に加え得点更新セルも同一の選択操作へ接続。キーボード入口はbuttonとして維持。

4. 統合レビューで保存が直近12件のため通算回番号が正しくないことを発見。最新/何回前へ変更し、選択は保存session内容をキーにする。更新なしの詳細重複も除去。
