# 探索中の進捗更新の停止対策

## 修正

- 定期保存の完了を探索ループ内で待たない。同時保存は1件に制限し、停止時には実行中の保存を待ってから最終状態を保存する。
- 保存開始後に探索が進んだ場合は未保存として扱う。定期保存の失敗は停止要求と競合してもエラーとして残す。
- 3Dビューは状態・カメラ・選択・表示設定が変化した時に描画する。カメラの減衰と非表示からの復帰は継続して検知する。
- ノードの物理状態は不変なので、探索メタデータの更新だけでは同じフレームを作り直さない。

進捗には実際の処理記録を使う。更新待ちの判定時間や進捗値の補間は変更していない。

## 検証（2026-10-15）

ローカルVite開発環境で既定構成の探索と3Dビューを同時表示して確認した。

- 修正前の15秒計測では、進捗受信間隔は最大428ms。Worker側103msの区間が画面側402msになる遅延もあった。停止中のプロファイルでもThree.jsの描画処理が継続していた。
- 修正後の停止中プロファイルは大半がidleになった。
- 修正後、他のビルド・テストを終了して10秒探索を2回計測。受信間隔の最大値は270msと258ms、95パーセンタイルは両方約224ms。後者ではDOM監視でも「更新待ち」が出なかった。
- ビルド・全テストと重ねた初回計測では最大1766msだった。CPU競合がある状況まで遅延を解消したとは扱わない。また、この計測でユーザー環境の周期的停止を再現できたとは断定しない。
- 上面・斜視の切替、別ノードと初期ノードへの移動でcanvasの表示が変わることを確認した。
- 遅延させた保存中にも探索件数が増えること、停止時の保存直列化、保存内容の一致、再開、保存失敗の扱いを自動テストした。
- 全194テスト、型検査を含むビルドが成功。

進捗通知の目標は約100msだが、1回の探索処理やブラウザの負荷により間隔は伸びる。今回の修正は定期保存待ちと静止中の不要な3D描画を取り除くもの。
