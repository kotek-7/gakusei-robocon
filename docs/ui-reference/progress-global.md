# 全画面共通の計算表示

担当: global_feedback。対象: `web/src/shell/StatusBar.tsx`、`shell/progress/summary.ts`、`style.css`末尾。

## 観察と配置

変更前は候補探索の開始時刻からローカルタイマでバーを進め、同じ行に候補探索の累計、全探索の局面・遷移・構成、未完了表示を並べていた。Workerの準備や保存状況を表示できず、どの処理の数値か判別しづらかった。開始要求の応答前は表示が変わらなかった。

| 部品 | 対象・意味 | 配置理由 |
| --- | --- | --- |
| 現在の処理名 | 選択中の探索の状態 | 作業画面を移動しても見えるステータスバー左端。準備・評価工程・最終保存・終了理由を区別する |
| 経過と処理数 | 今回の処理の計測値 | 処理名と同じボタン内。Workerの経過秒を使い、評価は完了構成数、全探索は処理行動組数を示す |
| 停止 | 実行中の計算への操作 | 状態に隣接し、狭い画面でも縮めない。停止要求の応答待ちと最終保存中は再操作を無効化する |
| 計算詳細 | 計算パネルへの移動 | 実行中に明示し、状態表示自体からも開ける。停止と合わせて常用操作の位置を固定する |
| 累計・保存詳細 | 対象探索の記録 | 計算パネルへ集約。ステータスバーでは同時に複数種類の累計を並べない |

1000px未満では右側の再生位置などを非表示にして計算表示を優先する。560px未満では計測数値を省略するが、状態・停止・詳細導線を残す。完全な説明は状態のtooltipにも含める。数値の更新はlive regionに含めず、処理名の変化だけを通知する。

## 参照

[VS Code 1.96.0 progressService.ts](https://github.com/microsoft/vscode/blob/1.96.0/src/vs/workbench/services/progress/browser/progressService.ts)の`withWindowProgress` / `updateWindowProgress`を確認。タイトル・進捗メッセージ・詳細を開くcommandを同じstatus entryに持たせる構造を採用した。`withNotificationProgress`のキャンセル操作も参照した。今回はソース確認のみで、VS Codeの画面実操作はしていない。

VS Codeの通知スタックや表示遅延は採用しない。このアプリは選択中の探索を対象とし、開始クリックの応答を直後に表示する必要がある。時間枠に対する割合を探索網羅率として扱わないため、共通バーの割合表示は撤去した。
