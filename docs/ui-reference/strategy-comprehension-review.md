# 選んだ作戦を理解するための独立レビュー

担当 `/root/strategy_comprehension_review`。2026-10-15。実装編集は行わず、StrategyPlan、detail/index、selection、実行解析と意味検証記録、親が取得したdesktop/mobileスクリーンショットを確認した。ブラウザーは親専有のため、この担当自身の実操作は0回。レビューは以下の3巡。子への委譲なし。

## 1巡目: 最初の画面で分かる仕事

実データの画面はTR25手順、BR31手順。上からTRの移動、取得、受け渡しが続き、BRの仕事や建設・反転の順序は初期表示に現れない。390pxでも同じ問題がある。全文の指示を公開しただけでは、両機が何をする作戦かの把握を利用者へ委ねている。

必要な修正:

- 固定指示の前に、赤TR/赤BRそれぞれの「指示の概要」を2行の属性表で置く。動作種別と対象を、実際のoperationだけから抽出する。例は「取得 → 直接渡す → ムスティカ取得」のような順序付き表現だが、取得物がMであることをdemandから確実に読めた場合に限る。
- 長い全文リストの初期表示は、移動先・操作・資材条件を別行へ過剰に展開せず、番号/動作/場所の表を基本にする。資材条件の詳細は選択行の横または下に置く。折り畳みやメモ機能は再導入しない。
- 機体別概要から対応する手順へ移動できれば、簡約によって失った細部を直接確かめられる。番号は機体内番号とし、両機の同番号を同期と見せない。
- 作戦の予定と選択展開の結果を同じ要約へ合成しない。概要に「運搬役」「建設役」と役割だけを書いても、全候補に共通する説明なので候補理解には足りない。

## 2巡目: 根拠を失わない短い表現

`CandidateInstructions.red` は固定指示、`candidate.plan` は相手待機時に完了した建設等の圧縮結果。現在の見出し「建設6→建設7」は後者だが、その出所が見える箇所は下方の?にある。相手応答を選んでも見出しは変化しないため、選択展開の結果にも見える。

採用すべき表示契約:

| 表示 | 取得元 | 短い表現と制約 |
| --- | --- | --- |
| 機体別に何をするか | redのoperation列 | 「直接渡す 6指示」「設置先 S6 → S7」。指示数であり完了回数ではない |
| 移動先 | travel.dest | 連続重複だけ省いた場所列。最短経路の全通過地点とは言わない |
| 建設・反転の到達結果 | candidate.plan | 「相手待機時の完了：建設 S6 → 建設 S7」。完成塔と呼ばない |
| 相手を変えた結果 | 選択evidence/analysis | 赤青得点・実行記録・不成立。作戦の固定指示自体を変えない |
| 必要な資材条件 | operation.demand | 取得/設置時の物体条件。繰り返し登場を必要総数へ足さない |

概要の最低限は、機体ごとの動作種別、建設/反転の対象順、指定時刻待機の有無。全文で読める全命令を再び概要へ並べる必要はない。動作と対象の組を連続圧縮し、再訪は残す。移動を除いたoperation順序に表示番号を新設せず、元の手順番号へのリンクを保つ。

未採用: 「速攻」「安定型」「妨害型」「高得点狙い」等の戦術名。現データから意図を証明できない。地図矢印だけによる概要も、運搬物/受け渡し/建設を説明できないため補助に限定する。

## 3巡目: 概要を足した後に残る子課題

- 完了結果を冒頭へ移す場合、相手待機と現在選択中の展開の違いを可視ラベルで示す。?だけに重要な対象範囲を隠さない。
- 固定手順の不成立行には時刻移動があるが、他の行は実行済/未到達を示していない。「不成立表示なし」を完了と解釈させない。未到達表示には固定指示と実行記録の対応データが必要。現在のabsenceから推定する実装は禁止。
- TR/BRを同時に把握する入口が必要。機体selectは全文を絞るには有効だが、BR存在の発見をこれに任せない。
- 移動先を場内で選択する操作は、現在のplan結果には存在するが固定travelにはない。目的地選択だけを別操作として追加する余地がある。実行時刻を勝手に補わない。
- 「相手待機」で青手順がない状態と、相手応答で青手順がある状態を切り替え、赤の指示概要が変わらず青の閲覧対象だけ増えることを確かめる。
- 操作名には既存actionNameを利用するが、概要で物体IDまで全部並べると識別子が主役になる。資材条件は既存instructionResourcesで読む詳細へ残す。

## 配置の参照と検証

`strategy-plan.md` に記録済みの添付PDF p.45/51のInspector構造とGodot 4.5-stableの対象追随を再利用できる。ただしこれは属性を選択対象に結びつける根拠であり、長い指示一覧を上から読ませる根拠にはならない。今回の担当はPDF画像やOSS実機を再確認していない。

スクリーンショットで確認した事実は初期viewport内の情報の偏りと手順の長さ。所要時間短縮やクリック削減の測定は行っていない。親には、赤TR/BRの概要の初期表示、相手待機ラベル、未実行を完了と見せない表現の検証を引き継ぐ。

終了理由: 編集禁止の独立レビューとして、作戦理解を妨げる現画面の具体位置、必要な表示、実データによる導出契約と反例を特定した。未到達手順の判定、資材供給と使用の対応、地点から指示への逆引きは未実装の子課題として残る。全機能の探索終了は主張しない。
