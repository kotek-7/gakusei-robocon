# 候補単体の相手展開・弱点解析

対象: `StrategyOpponents.tsx`, `opponentAnalysis.ts`, `opponents.css`。相手手順ごとの結果を調べ、赤の固定指示に繰り返し現れる不成立から実際の記録へ移動する。

## 配置と操作

- 相手展開: 一覧の「N展開を見る」から、その手順に属する全記録へドリルダウンする。別のカードを下に積まず、同じ表領域を置き換える。相手IDは詳細の見出しで全文を表示。
- 展開ごとに赤・青得点、点差、相手待機時からの赤得点増減、不成立になった機体・指示・時刻を表示。「得点を見る」「実行不可を見る」はその記録オブジェクトを親へ返し、経路を含む既存の選択機構へ接続する。
- 固定手順の弱点: 同じ赤指示・理由を集計し、全該当記録を一覧化。最初の1件だけを代表にしない。不成立時刻はその指示・理由に一致するものだけを表示する。
- 戻ると起点ボタンへフォーカス復帰。開始時は戻るボタンへフォーカス。親は search/run/candidate でビューをkey指定する契約。更新されたオブジェクト参照には依存せず、計算中の更新でドリルダウンを解除しない。
- 相手一覧・展開一覧は50件ずつ。フィルタ・対象切替時にはページを先頭へ戻し、件数減少時も最終ページ以内に収める。
- 赤の増減は正負付きの範囲。赤得点が上がる記録を「負の減点」と呼ばない。ID未記録の古い結果を、同一相手手順だと推定してまとめない。

## 巡回記録

各巡はソース・データ確認と実装であり、ブラウザ操作を担当者が実施した回数ではない。実画面は親担当が共有ブラウザで検証する。

1. 相手集計に最小/最大以外の記録への入口がない。展開一覧・記録ごとの得点/診断移動を実装。
2. 弱点から最初の記録しか開けない。同じ指示・理由に該当する全記録を点差順に列挙し、正確な時刻・経路へ接続。
3. 増加した得点が負の減点として表示される。赤の増減範囲へ変更し、混在・増加のみのテストを追加。
4. ID未記録の同一視、計算中更新で選択消失、戻った際のフォーカス消失を確認。個別集計・親key契約・フォーカス復帰を実装。
5. 他担当の独立レビューで大量記録時のspreadと配列コピーを指摘。scalar reduce、push、140,000件テストを追加。不成立集計も記録内Setで重複排除し、全過去記録へのincludesを廃止。
6. 追加レビューで全行描画とindexOfを確認。50件ページングと参照→番号Mapを追加。フィルタ/対象変更によるページ範囲も再検討。

## 検証と残る範囲
