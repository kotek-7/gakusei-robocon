# 計算と進捗パネルの見直し

2026-10-15。対象は `web/src/editors/jobs`。担当 jobs_panel、委譲元 root。作戦や評価の意味は既存モデルに従う。

## 観察と配置

開始操作の後も、旧パネルの先頭は計算方式の選択と次の計算設定だった。経過時間は候補探索の累計だけを示し、評価の保存結果と実行中の処理が同じ領域に並んでいた。

| 対象 | 意味・使用場面 | 配置と理由 |
|---|---|---|
| 今回の計算 | 実行状態、経過、停止 | 方式選択の外側・先頭。保存結果の表示を切り替えても実行中の計算と停止操作が残る |
| 制限時間 | 今回の実行上限 | 今回の経過と併記。進捗バーは時間消費を示すと明記し、探索全体の完了率に換算しない |
| 全探索の行動組数 | 今回処理した行動組と予算 | 累計局面数と分離。今回の実測件数を分母と照合できる |
| 評価の処理段階 | 現在処理中の集計 | 今回の計算内に段階名・件数・構成を配置。段階の分母を全体進捗に使わない |
| 保存状態 | 中断・終了前の確認 | 経過の隣。最終保存中も実行として表示し、完了を先に示さない |
| 結果を見る | 作業領域への移動 | 今回の計算末尾。候補・評価・局面に直接戻れる。結果がなければ無効 |
| 次の実行設定 | 値の編集、実行 | 状態の下。実行中は値の編集を無効にして現在の制限との食い違いを防ぐ |
| 累計・履歴・構成別結果 | 保存済みの範囲を調べる | 既存の方式選択の下。履歴フィルター・同じ予算で再開・構成別絞り込み・書出しを維持 |

進捗をモーダルに移す案は、計算中に候補や局面を確認できなくなるため不採用。全体の推定残り時間は、探索対象数が確定しないため不採用。更新件数を新たな装飾カードにする案は、今回と累計の区別を弱めるため不採用。
