# 計算中の探索表示

対象は `editors/jobs/LiveSearchTrace.tsx`、配置は今回の計算の時間枠・行動組数の直後。通常の進捗と同時に、実際にどの局面を処理しているかを確認する。

## 参照

- Godot 公式 Debugger panel の Visual Profiler / Monitors: https://docs.godotengine.org/en/stable/tutorials/scripting/debug/debugger_panel.html （2026-10-15参照）。公式スクリーンショット `debugger_visual_profiler_results.webp` を確認。操作画面の上部に制御、左に対象と数値、右に実測履歴があり、停止後は履歴が固定される。Godot実機は未操作。
- Godot `4.4-stable`, `editor/debugger/editor_performance_profiler.cpp`, `_monitor_draw` / `add_profile_frame`: https://github.com/godotengine/godot/blob/4.4-stable/editor/debugger/editor_performance_profiler.cpp 。実測値の受信でhistoryを更新し再描画する構造を確認。UI自身のタイマーで活動量を増やさない構造を採用。
- 本アプリではフレーム性能ではなく局面展開を扱うため、CPU/GPUの折れ線や選択対象一覧は移植しない。実際の探索遷移を線で示し、処理している局面を枠付き点で区別する。

## 配置と意味

| 表示 | 意味と配置理由 |
| --- | --- |
| 直近の探索 + ? | 全グラフではなく有限の受信記録。常設の説明文は置かず、上下位置に意味がない点や記録範囲をヘルプに置く。 |
| グラフ | 横軸は固定した試合時刻。縦位置はIDから決めて再描画で揺れない。保持された実在の辺のみ表示。 |
| 処理局面・速度・処理数 | グラフの直下で現在の対象と仕事量を確認。候補探索は展開、全探索は行動組で単位を区別。 |
| 更新待ち | 1.5秒以上記録が来なければ明示。タイマーはこの判定だけに使う。 |
| 評価工程 | 評価では探索辺を捏造せず、実際の5工程を一直線で表示。工程が構成ごとに繰り返されるため、前工程を完了扱いで塗りつぶさない。既存の評価数値・バーと併用。 |

## 局所巡回

1. データ契約とOSS調査。force layout、擬似パルス、全履歴を保持する案を棄却。固定座標と有界の実観測を実装。
2. 状態レビュー。終了後の速度0を「最終測定値」と呼ばないよう、速度は計算中だけ表示。更新待ちでは速度を隠す。画面読み上げにはグラフ要約を付け、高頻度aria-live通知は行わない。
3. 狭幅レビュー。固定640px viewBoxは文字まで縮むため、ResizeObserverで実際の幅に座標だけ合わせる。狭幅では時刻目盛を3点へ減らす。高さ164pxを維持。点の配置・時刻の端点・ゼロ範囲・狭幅を3テストで検証。
4. 別担当のソースレビューを受け、終了評価の表示を「評価完了」に修正。成功完了時に実行中工程が無い状態を保持。中断は最後の工程が残る。モーション補間はなく、reduced-motionでも同じ実測値を表示。

型検査成功（初期実装・狭幅対応後）。実ブラウザでの計算中・停止・狭幅の確認は統合担当が実施する。孫担当の追加起動は同時実行上限により不可、独立レビュー担当との相互レビューを実施。

未採用: グラフのノードクリックから局面画面への移動。探索中の一時履歴IDと保存済み局面の選択同期を別途設計する必要があり、今回の観測表示の範囲から除く。速度の時系列グラフも既存の処理量と重複するため追加しない。
