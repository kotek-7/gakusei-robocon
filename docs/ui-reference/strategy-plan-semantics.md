# 作戦の要約と実行記録

担当範囲は作戦詳細の意味の検証。実装変更は親担当が所有する。ソースを5巡確認した。画面操作、OSS画面調査、物理検証はこの担当では実施していない。

## 1巡目: 作戦要約の出所

`web/src/engine/discovery.ts` の `evidence()` は赤チームの完了イベントのうち `place`、`flip`、`placeM` を `Candidate.plan` に変換する。連続する同じGoalは1件にまとめる。これは建設・反転・ムスティカ設置の順序であり、実行スクリプトではない。

採用する表示契約:

- 要約は「相手待機時」の結果として扱う。選択した相手応答の実行結果と混ぜない。
- 件数は要約の項目数。動作回数、完成塔数、必要物体数として表示しない。
- `build` に高さがなくても完成塔とは扱わない。アース1個だけの設置も同じ値になる。
- `[]` は建設・反転・ムスティカ設置がないことを示す。搬送や持ち直しが存在する場合がある。

## 2巡目: 固定手順と相手応答

候補IDは赤TR・BRのスクリプトをハッシュ化した値。`Candidate.baseline.strategy` は完了イベントを圧縮した分類IDで、同一の実行手順を意味しない。スクリプトは保存された探索状態にあるが、公開される候補からは除外される。

`planner.ts` の `fixedChoice()` は各ロボットの命令を別々に順番に処理する。移動は目的地への最短経路を継続し、時刻待機は指定時刻まで継続する。条件に合わない操作は待機し、最初の不成立が記録される。相手変更によって時刻・成立状況が変わるため、相手待機時の要約を相手応答の実行予定として提示しない。

## 3巡目: 個数、時刻、担当ロボット

`classification.ts` のmilestonesは設置・反転・持ち直し等の完了を残し、ロボット、地点、物体種別・個数、同時刻のまとまりを保持する。絶対時刻は取り除かれる。移動、取得、受け渡し、待機は含まれない。

作戦詳細で各情報を取得する場所:

| 情報 | 参照元 | 表示上の注意 |
| --- | --- | --- |
| 建設・反転順序 | candidate.plan | 相手待機時の圧縮要約 |
| 完了物体の種別・個数 | evidence.milestones | 同じ物体の再設置を必要個数へ合算しない |
| 全動作・時刻 | replay.events | start/finishを区別する |
| 保持物・配置・途中の動作 | replay.frames | 選択経路・時刻に従う |
| 不成立の命令番号 | evidence.blocked | ロボットごとの番号でありplanの行番号ではない |

`duration()` は設定内の速度区分と経路辺に依存する。moveは距離/速度を切り上げ、他の操作は設定値を切り上げる。複数物体の操作でも個数を掛けない。要約から合計所要時間を算出する案は不採用。

## 4巡目: 反例と検証データ

以下は意味の退行を防ぐ単体テスト候補。実装担当へ共有済み。

1. `[{kind: "build", spot: 0}]`: アース1個設置と3個設置の両方がこの要約になり得る。完成塔数・必要3個等を推定しない。
2. `[{kind: "build", spot: 0}, {kind: "flip", spot: 1}, {kind: "build", spot: 0}]`: 同じ地点への再訪を保存する。対象地点数は2、建設の要約項目数は2。
3. `[]`: 「作戦なし」「何もしない」と表示しない。
4. `[{kind: "build", spot: 999}]`: 保存データの未知地点を描画例外にしない。地点選択への移動は無効にする。
5. `[{kind: "flip", spot: 0, at: 0}]`: 時刻0をtruthy判定で消さない。ただし現行discoveryはatを出力しない。
6. 赤の要約に対して青側の同名地点を選択しない。モデルの地点IDは`spot0-0`のようにチーム接尾辞を持つ。
7. 同じstrategy IDでcandidate IDが異なる候補を別候補として扱う。
8. 不成立のinstruction=2を要約の3行目へ結び付けない。

## 5巡目: 表示契約と追加案

地点名、階層、共有/専用の情報と、フィールド上の地点選択は要約だけでも実装できる。計測値の出所が明確で、詳細化に有用なため採用対象とする。能力・速度区分は同じrunのvariantを参照する。

詳細な移動、待機、直接受け渡し、途中停止の把握には選択経路の再生イベントが必要。要約専用コンポーネントでは推定せず、実行経路の担当領域へ接続する。これは担当範囲外のデータ依存であり、未処理の局所機能として要約へ足し続けない。

折り畳みや説明段落の追加は行わない。意味の制約は既存の「?」で短く伝える。表示候補は「相手待機時に完了した建設・反転・ムスティカ設置。連続する同じ作業をまとめています。」。部品単位の配置とブラウザ検証は親の作戦詳細記録に残す。

終了理由: 要約に含まれる情報、失われる情報、別の取得元が必要な情報をコードの出力経路まで確認した。実装への接続と反例を共有済み。独立した子担当の起動は行っていない。
