# 作戦詳細の動作解析

対象: `strategy-detail/StrategyExecution.tsx`、`execution.ts`、`execution.css`。

## 既存機能との境界

既存 `timeline/IntervalEditor.tsx` は機体別の稼働/待機、最長待機への移動、動作種類別の件数/秒数、選択範囲での区間詳細を持つ。`timeline/index.tsx` は全機体のガントとイベントを持つ。したがって「既存で動作解析ができない」とは判断していない。今回の詳細面は選択作戦の文脈の中で記録を調べる入口であり、独立した再生エンジンではない。

追加した解析は、移動とその他作業の時間分離、記録で覆われていない時間、選んだ動作と時間が重なる他機体の動作/秒数、動作・場所・物体の検索、長い順。元の手順の意図や失敗理由を時間だけで推測しない。

## 対象と配置

| UI | 対象・意味・使用場面 | 配置・状態 |
| --- | --- | --- |
| 解析開始/終了 | 展開の時間範囲 | 集計の直上。空入力/逆転は未集計。全区間で復元 |
| 機体別時間表 | 選択期間の記録から得る結果 | 4機体を同時比較。機体名で一覧を絞込。フィルターで集計値は変えない |
| 動作検索/並び順 | 記録を探す | 台帳の直上。文字列は既存の競技語彙を利用 |
| 区間台帳 | 動作の選択 | native radioで対象を明示。開始/終了と場所を同じ行で読む |
| 選択動作と重複表 | 選択区間・他機体の時間関係 | 台帳の下、絞込で消えた他機体も表示。開始/終了と重複開始への移動を近接配置 |
| ? | 集計の意味 | 未記録と待機、同時と協調を混同しないための短い補足 |

一時的な解析条件は経路の変更でリセット。予定終了は記録終了と区別して表示し、打切り区間から完了を断定しない。

## 参照

UIカタログの選択同期、一覧を離れない詳細、時間関係にタイムライン/表を対応させるパターンを参照。PDFをテキスト抽出し、選択した行と時間を基準に周辺情報を読む構造へ適用した。SVG図の視覚確認は担当内では未実施。

OSS根拠は `candidate-diagnostics.md` の VS Code 1.96.0 `src/vs/editor/contrib/gotoError/browser/gotoError.ts` 調査を再利用。課題は記録を選択して該当位置へ移動すること。選択と移動を別操作にする部分が今回にも適合する。ファイルを横断するショートカットや修正操作は移植しない。新たなOSS実機検証はしていない。

## 巡回

1. 既存コードレビュー。時間集計の多くが既存機能と確認。欠けている他機体との重なりと未記録時間を局所採用。新たなタイムライン描画は既存と重複するため不採用。
2. データ契約レビュー。`analysis.intervals` の実際の終了と `planned` を分離。探索開始前の区間をクリップし、待機秒を予定時間から算出しない。共通 `intervalDetails` を再利用。
3. 台帳実装後の操作設計レビュー。時系列だけでは長い動作を探しづらいため長い順、動作/場所/物体検索を追加。機体絞込で他機体の文脈を失うため重複表は全機体から算出。
4. 数値検証。部分区間・予定終了・空範囲・同時区間端点を3テストで確認。未記録は区間の和集合から算出。負の時間を発生させない。
5. 接続前レビュー。複数インスタンスのradio名の競合を `useId` で除去。部分区間の「開始場所」を「動作開始場所」へ訂正し、切り出した時刻の位置と誤読させない。型検査成功。

上記はコード・計算・操作設計の5巡であり、5回のブラウザー実操作ではない。ブラウザーは統合担当が既存機能レビューと接続後の確認を行う。未確認の実操作を検証済みと数えない。

## 残る枝

- 実際の探索経路で開始/終了への移動が対応する機体を選ぶこと、狭いペインで表の水平スクロールと重複表が使えることは統合確認待ち。
- 記録がない時間の理由や動作間の因果は分析データから確定できないため追加しない。
- 動作を変更して再評価する編集は計算契約を伴う別作業。今回の記録解析には混ぜない。

担当は1名、孫委譲はなし。同時実行枠を他枝の孫調査へ残し、この枝は親との接続契約内で実装した。局所の計算検証が完了したため統合へ引き継ぐ。

接続前の追加確認で、固定ヘッダーの背景変数を既存の `--surface` に合わせた。未定義の背景でスクロール行がヘッダー越しに透ける問題を防いだ。
