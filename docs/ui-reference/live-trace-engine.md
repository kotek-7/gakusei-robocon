# 実行中の探索トレース

対象: Worker の実際の展開処理を、計算結果・保存済みグラフと区別して表示するための一時データ。

## 契約と採否

- `job.activity` を約100ms間隔で発行する。既存の `search.changed` と独立させ、候補一覧全体の高頻度再描画や discovery の全量転送を追加しない。
- `ActivityTrace` は最大48局面・64遷移。古い局面と、その局面を参照する遷移を除外する。全探索グラフや網羅率とは呼ばない。
- 局面IDは、通常展開では `e:<StoredNode.id>`、候補探索では `d:<DNode.id>`。候補探索は同じ実局面でも固定指示・履歴が異なるため、実局面IDだけで併合しない。
- リンクは通常展開の `StoredEdge`、候補探索の実際に追加した `DiscoveryState.links` に対応する。位置・リンク・作業中表示をタイマーで捏造しない。
- 通常展開の単位は両陣営の行動組合せ、候補探索の単位は履歴局面の展開試行（終端・不成立を含む）。評価は既存の `EvaluationProgress` の工程別件数をそのまま利用し、工程リセットを速度として解釈しない。
- startingで空のトレースを配信。saving/finishedも配信し、停止後は更新しない。保存内容に含めず、再読み込み後の静的グラフとして装わない。
- トレースは各計算チェックポイントでのみ発行する。重い単一処理や保存中も一定周期で動く、といった保証はしない。

## 巡回と検証

1. discovery と exact の処理とID体系を読んで、状態ノードだけを表示する案を却下。履歴ノードとの名前空間分離と実リンク採録を実装。
2. 高頻度の全Search転送案を却下し、独立イベント＋上限付き最近集合へ。スナップショットを複製して後続変更の混入を防止。
3. 停止・初期保存失敗・再開始を再確認し、最終イベントと collector 解放を追加。評価の速度誤表示を防ぎ工程件数のみ提供。
