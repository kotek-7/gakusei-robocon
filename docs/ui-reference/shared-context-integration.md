# 共通状態表示の統合記録

## 作業範囲と配置

候補一覧の選択、現在の再生経路、比較A/Bに固定した経路をそれぞれ識別する。既存の上部欄に「表示中」の入口を一つ置き、構成・候補・相手・局面・選択物と元候補への移動を展開時に表示する。新しい常設行、全体用の比較カード、常設Inspectorは増やさない。計算進捗と再生時刻は下部に残し、同じ計算パネルを開く重複ボタンを除いた。

調査は提供PDFのp21/p24/p35/p45と、VS Codeのパンくず、BlenderのProperties固定対象を扱った。公式画面と固定リビジョンのソースを確認し、各アプリ本体の操作とは区別した。詳細は `shared-context-patterns.md` に記載。

変更前の実データでは、一覧の選択候補と3Dに表示する局面が異なり、共通欄には候補の由来がなかった。変更後は一度開けば由来を確認でき、そこからもう一度の操作で元候補詳細へ移動できる。作業時間の短縮率は測定していない。

## 担当と見直し

親を含む7担当、最大委譲深さ2。状態契約3巡と下位レビュー2巡、経路接続4巡、表示UI2巡と統合修正、比較5巡、パターン調査3巡。親は接続、状態遷移、狭幅の統合確認を担当した。

実装後に見つけた問題は、候補由来の失効、履歴の構成番号、非同期の経路取り違え、未設定Aが現在経路を表示する挙動、狭幅の探索select縮小とpopupはみ出し、同名候補の識別、狭幅の選択物の確認先。これらを既存領域で修正した。新たな全体バーや一括の同期設定は今回の作業には追加しなかった。

## 自動検証

- 全179テスト成功。
- 型検査を含むproduction build成功。既存の依存ライブラリーとchunk分割に関する警告は残る。
- `git diff --check` 成功。
- Impeccable detectorを変更した共通表示・比較・3Dの表示コードに実行し、指摘なし。

## 検証条件と制限

終盤174秒から候補5件・共通相手8件を探索した実データを使用。ブラウザーの機能検証はWebGL無効のため、3D描画品質の検証とは扱わない。Vite経由で内部状態を読む場合、HMRのタイムスタンプ付き実モジュールを参照する必要があり、拡張子だけ指定した別インスタンスを使った初回の検証結果は破棄した。

既存のURLの経路長制限により、2000辺を超える経路とその由来は共有URLへ含めない。比較の保存は探索のworkspaceデータに保持する。今回は大会モデルや評価条件を変更していない。

## ブラウザー統合確認

実resource URLを使った検証で以下が成功した。

- 候補の「3Dに表示」から試合解析・条件へ移動しても出典を保持。
- 共通入口から元候補詳細へ移動しても経路と再生時刻を保持。
- 一覧で別候補を選んでも現在の再生経路は変化しない。
- Escapeで閉じて起点ボタンへフォーカス復帰。
- 1280px、900px、390pxで横はみ出しなし、再生位置は表示を維持。
- 再読込後も再生出典と比較Aの出典を復元。
- 手動で初期局面へ移動すると古い候補由来を解除。
- 390pxで非nodeの選択「赤BR」をポップオーバー内に表示。この項目は状態を注入して表示を検証し、3Dでのロボット選択操作は検証対象外。

比較表の統合画像で、候補・相手の長いIDがB列を押し出す問題を発見した。既存の短縮IDと全文titleを使い、表の折返しと列幅を修正した。

比較修正後はA/B両方を割り当てた画面で両列が表示幅に収まることを確認した。実際の経路selectorで「A 未設定」を選び、「現在の経路」へ戻す操作も成功した。WebGLが無効のため、未設定経路の描画内容そのものはこの操作確認には含めていない。
