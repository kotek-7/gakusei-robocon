# 計算領域の配置見直し

対象: `editors/jobs/index.tsx`、`jobs.css`、`Coverage.tsx`。担当 progress_layout、下位独立レビュー layout_review。

## 配置の根拠

- 計算種別は編集対象の切替。予算と開始ボタンを同じ toolbar に配置し、設定見出し・独立実行バーを撤去した。制限時間は候補探索、行動組数は全探索だけに適用する。評価は行動組数の右隣の連続ボタンにせず toolbar 右端に置いた。
- 今回の実行は toolbar の直下に一つ。計算種別切替をしても実行中の停止対象を変更しない。CurrentJob の kind と停止操作は live 担当の実装に委ねる。
- 全探索の保存結果は局面・遷移・展開済み局面・探索済み構成を一行の表にした。四つの独立した metric 枠を廃止し、同じ保存範囲の値として読める。
- 構成別結果は比較可能な列を維持。未着手は値 0 の実行行に偽装せず、表末尾に未着手構成数と結果なしを明示。構成 ID はその構成へ移動するリンクを保持した。
- 横幅が狭い場合も結果行をカードへ変換しない。表内で横スクロールし、構成列を固定する。次の実行設定は折り畳まない。
- 候補探索全体の未保証文は DiscoveryProgress に一度だけ置く。構成表末尾の同文は撤去。

参照: `progress-structure-patterns.md` の PDF p69（ジョブ監視）、Blender 4.3 の対象・進捗・停止の一体表示、VS Code の文脈内進捗。PDF と公式画像・固定リビジョンの実装を参照した。外部ソフト自体は操作していない。ジョブ一覧の大きな独立画面や全体通知は、この単一実行アプリへ追加しない。

## 巡回

1. 既存コードと root が取得した変更前画面を確認。設定・保存結果 select、実行バー、累計、折り畳み、説明、構成見出し、フィルタ、表、重複説明という階層を整理。常用操作を設定 toolbar に統合した。
2. 変更後のアプリを実操作。探索タブから計算と進捗を開き、候補探索→全探索・評価を切替。1440px 画面、999px jobs 領域のスクリーンショットを確認。全探索未展開を「未探索の分岐あり」と断定しない文言へ変更した。
3. 下位担当が独立レビュー。表内 overflow と、非 embedded 評価の対象名欠落を発見。前者を修正、後者は live 担当が「前回の評価」ラベルで修正した。独立担当は修正後の第3巡まで確認し、追加の必須修正はなし。700px 画面と390px画面で操作し、jobs の clientWidth/scrollWidth がそれぞれ692/692、382/382となることを確認。狭幅で開始ボタン・種類切替が表示され、表だけが横スクロールすることを画像で確認した。

## 検証

- `npm run typecheck` 成功。
- Playwright + Chromium、既存の実行済み探索を含む IndexedDB fixture を使用。設定切替・実行入口・結果表示を確認。
- `/tmp/progress-layout-wide.png`、`/tmp/progress-layout-exact.png`、`/tmp/progress-layout-narrow.png`。
- WebGL 無効で検証。3D 描画の検証はこの枝の対象外。
- 未着手集約はコードレビューで確認し、全構成に着手済みの既存 fixture では未着手表示の実描画は未検証。root 統合で異なる実行状態を確認する。

未処理の機能追加はない。数値列や操作を増やす案、結果をカードへ分解する案は比較対象の対応関係を弱めるため採用していない。実行・履歴・全体レイアウトを統合した最終実操作は root に引き継ぐ。
