# 候補内の対応記録：独立担当の再帰レビュー

2026-10-15。担当範囲は候補選択後の対応一覧。共有候補一覧・3Dコマンド・保存状態は親が所有する。4枠が全て稼働中のため、この担当内の子課題は順次巡回した。実装前に候補を固定数へ制限せず、以下の作業枝を親へ報告した。

## 読取と根拠

`CandidateEvidence`は得点・結果経路・完了動作・実行不可の記録。相手手順の内容そのものは含まれない。`responses`の相手ハッシュ、`shared`、構成内`commonOpponents`を区別する。結果経路に含まれる青の動作を、固定した相手計画と説明しない。ABUルールの有限・簡略モデルへの対応と点差比較の限界は`candidate-expansion-research.md`と`docs/model.md`を照合した。

参考PDFはカタログとして読取。36「Single source of selection truth」、55「Compact labeled controls」、66–67「Sortable headers / Enterprise filtering」に対応する。列が少ない狭いInspectorなので、多列ヘッダー操作の模倣ではなく局所の絞込・順序メニューを採用した。

Godot 4.5-stable [InspectorDock](https://github.com/godotengine/godot/blob/4.5-stable/editor/docks/inspector_dock.cpp)の`_get_current_resource`、`_prepare_resource_extra_popup`、`_prepare_history`を再確認。安定IDから現在対象を解決し、履歴をIDで重複除去して現在対象を示す。[公式Inspector画面説明](https://docs.godotengine.org/en/stable/tutorials/editor/inspector_dock.html)も確認した。Godot実機の実操作は未実施。本アプリでは選択キーを親が所有し、表示順や絞込で選択対象を勝手に置換しない。Godotのリソース編集・保存は導入しない。

## 第一巡：作業の枝から構造を選ぶ

| 作業 | 不足 | 採用・配置 |
|---|---|---|
| 同じ相手に対する複数結果を調べる | ラベルの末尾が短いハッシュで、何件あるか分からない | 相手セレクトに全ID・件数。選択相手の記録数と点差範囲を一覧上に表示 |
| 共通比較だけを追う | 共有フラグだけで同条件と誤解し得る | `shared`と`commonOpponents`の両方を確認し行に種別を表示。共通比較外を別に絞れる |
| 不利・不成立の対応を探す | 全行を読むしかない | 点差負・実行不可フィルター、点差昇順・実行不可件数順を局所メニューに収容 |
| 基準からの劣化を知る | 赤青得点だけで暗算が必要 | 選択展開の点差と相手待機との差を一覧下に常設。因果や実機性能の差とは呼ばない |
| 前に見た対応へ戻る | 並び替えで行番号が変わる | 親の安定IDを維持。履歴の追加は比較A/Bとの目的重複が大きいため今回は保留 |

## 第二巡：追加した操作の子課題

- 相手ごとの集計 → 「共通最小点差」は元の対応のショートカットであり、相手待機も対応ではない → 集計から両方を除外。重複計上しないテストを追加。
- 共通比較の絞込 → `shared`であっても相手が共通リストにないことを考慮 → 共通比較外と表示し、個別探索由来とは断定しない。
- 絞込 → 選択中の展開が一覧から消える → 選択を保持し、「絞込の対象外」と復帰操作を表示。3D・比較割当の親コマンド対象は変えない。
- 隠れた選択 → 全行が`tabIndex=-1`になる → 可視先頭行をTab入口にする。そこへフォーカスした時点で明示的に選択を移す。
- 並べ替え → 同点行が毎回動く → 元順で安定整列。入力optionsを変更しない純粋関数に分離。
- 狭いInspector → 全機能を常設すると列を圧迫 → 頻用の選択・得点は表、表示条件はネイティブselectを含むdetails。Escで閉じてsummaryに復帰。
- 全ID → 省略ラベルでは区別できない → 相手選択肢には全ID、行にもtitle。結果動作で架空の相手名を作る案は不採用。

## 次の再評価候補と打切り理由

- 裁定分岐の原因別グループ：現行evidenceに裁定原因がなく、結果経路から推測すると誤表示。エンジンの記録契約を先に拡張する必要があるため保留。
- 相手計画そのものを表示：ハッシュから復元できないため保留。完了milestoneで代用しない。
- 応答閲覧履歴：同候補内での復帰操作とA/Bで代表タスクを扱える。大量候補の実観察で追加価値を確認してから採用。
- 対応のブックマーク・注釈：候補注釈とは別の保存契約が必要。現在の候補判断・比較スロットとの重複を観察してから検討。
- 分布ヒストグラム：記録の頻度は実際の確率ではない。点差範囲と件数で記録範囲を示す方が誤認を抑えられるため不採用。
- 全候補への一括相手固定は親一覧、複数候補の行列比較は別担当が所有。二重のグローバルフィルターを作らない。
