## 現行アプリで修正する配置上の問題

- `defaultWorkspaces()` の試合解析は最初から6領域を同時表示する。3D、タイムライン、対象一覧に加えて、イベント・属性・得点が固定分割され、小さいパネルの内部にさらに操作が積まれる。同時照合する主要領域を残し、代替的に参照する補助情報を同じドックで切り替える。
- 各エディタの縦積みされたセクションは、入力、選択対象の情報、全体の集計、実行操作を同じ読み順に置いている。表の上は検索と対象操作、右側は選択対象の属性、実行条件は専用の設定面という責務へ戻す。
- 比較画面のA/B、試合解析の3D/タイムラインは同時参照が必要である。この対はタブで隠し合わず、分割表示を維持する。
- 説明文を新しいページ階層に再編しても、操作対象と操作範囲は明らかにならない。機能そのものを適切な場所へ移し、長い背景説明が必要な場合だけ既存のヘルプを使用する。

## タブ付きドックの実装で守る条件

1. エディタを開くコマンドは、現在選択中の `editor` だけでなく非選択の `tabs` も検索し、既存のドックを選ぶ。テンプレート検索にも同じ規則を適用する。
2. ワークスペース切替・領域削除・配置リセット後の `activeArea` と `activeEditor` は、可視領域に一致させる。フォーカスした対象に対してショートカットが実行されることを検証する。
3. タブごとに固有の状態を保持するか、状態を破棄する明確な境界を設ける。カメラの比較側指定や表のフィルターを、別エディタへ漏らさない。
4. ドックを開く操作はタブ選択とフォーカスを一緒に更新する。狭い画面の領域切替でも同じ規則を使う。
5. 配置変更の検証には、非選択タブのreveal、別ワークスペースへの切替、選択タブの状態、最大化からの復帰を含める。

この文書は開発時の判断根拠であり、アプリ内に新しい説明画面や機能カタログを設けるための仕様ではない。

## 実装と検証

- 補助ドックにタブと分離操作を追加。既定配置は3D・タイムラインを同時表示し、属性・得点・スポットは右ドック、対象一覧・動作履歴は左ドックで切り替える。探索では候補一覧と進捗を同じ領域で切り替える。
- メニュー・探索の選択と、ワークスペース・その計算操作を別の行に配置。領域ごとの重複したヘルプ入口を外し、既存の項目ヘルプとヘルプメニューを保持。
- 候補の行を選ぶと詳細領域が更新され、確認する展開、3D表示、比較A/Bを操作できる。フィルター・選択・応答選択を保持。応答キーは配列順ではなく候補・相手・経路の識別子から作る。
- 機体・物体・スポットを選ぶとプロパティがその対象の再生位置の情報を表示する。再生操作はタイムライン下部、表示設定は上部へ配置。
- 条件編集の能力と所要時間、評価の構成結果と比較、得点の再生位置と区間差分を、それぞれ作業に応じて切り替える。検討記録は一覧と選択した記録の編集を分ける。
- 新しい配置は `robocon.layout.v3` に保存。旧レイアウトを自動変換せず、新しい既定配置で開始する。探索・注釈・バックアップ形式は変更していない。

検証では実際に探索を開始・停止し、4候補が得られた探索から経路を開き、候補をA/Bへ設定して同時再生画面まで移動した。機体から運搬中のムスティカへの選択追従、得点タブとの往復、候補タブの選択保持、検討記録のメモ・判断の保存と経路復元、評価計算による6作戦の表示を確認した。画面幅1440pxと390pxで確認し、390pxでページ全体の横はみ出しはない。

自動テストでは非選択タブの表示、タブ固有状態、配置変更後の操作対象、最大化中のタブ分離、タブの矢印キーと再生キーの競合、絞り込み前後の応答同一性を追加した。既存のエンジン検証を含め69テストが成功。型チェック・本番ビルドを実施。Impeccableの検出結果は空。ビルドには既存の大きなチャンク、静的・動的import混在、HiGHSのnode:module外部化に関する警告が残る。
