# 候補一覧・比較・検査を往復する

2026-10-15。独立担当 #10 と子担当 navigation_countercheck (#12) による再帰レビュー。

## 観察と配置

容量担当の実機結果と現行実装を確認。680px以下の候補パネルでは比較表の後にInspectorが積まれ、選択行を検査するためにスクロールし、次候補を探すために戻る必要がある。広幅では同時参照が必要なので表示を排他的タブに置換しない。

`Candidates.tsx` の一覧・横比較・選択候補の直前に、領域移動だけを行う固定ナビゲーションを置く。表示切替ではないためタブの選択装飾を使わない。位置とキーボードフォーカスを同時に移す。Inspectorの見出しに「一覧へ戻る」を置き、Tab→Enterでも元の選択行から上下移動を再開できる。グローバルショートカットは追加しない。

| 対象と意味 | 状態・適用範囲 | 配置の理由 |
|---|---|---|
| 一覧への移動 | 選択行へフォーカス。一致なしなら空一覧の解除操作へ | 探索条件の解除も候補一覧の仕事なので常に有効 |
| 横比較への移動 | 取り置きありで有効。絞り込み外の候補も保持 | 一覧と比較の対象が異なっても到達経路を維持 |
| 選択候補の検査へ移動 | 有効な選択候補ありで有効。内部スクロールを先頭へ | 移動直後に候補IDと検査対象を読める |
| 一覧へ戻る | 現在の選択行へ戻す | 検査→次候補の反復を同じ位置から再開 |

## 参照実装

[VS Code 1.105.0 navigationActions.ts](https://github.com/microsoft/vscode/blob/1.105.0/src/vs/workbench/browser/actions/navigationActions.ts) の `BaseFocusAction.focusNextOrPreviousPart`、`findVisibleNeighbour`、`BaseNavigationAction.navigateBackToEditorGroup` を確認。可視領域を対象に移動し、再表示時にアクティブな編集対象へフォーカスを戻す契約を採用。[公式アクセシビリティ資料](https://code.visualstudio.com/docs/configure/accessibility/accessibility)の領域間移動と照合した。VS Code実機の操作は実施していない。F6やウィンドウ全体の循環は既存アプリの操作と衝突し得るので移植せず、候補パネル内の明示操作にする。

添付PDFのSplit viewを根拠にした前担当の `candidate-capacity.md` を再利用。関連情報を同時表示し続ける前提が今回も一致する。新しいドッキングやレイアウト保存は今回の移動タスクには不要。

## 子機能の再評価

新しい子担当に変更後のフォーカス・空状態を渡した。以下を別の枝として発見し、実装へ戻した。

- 0件の一覧でも条件解除へ戻りたい→一覧移動を無効にせず、フォーカス可能な空一覧を移動先にする。
- Inspectorがなくなっても右列が空いている→`has-inspector`がない場合、比較表を全幅にする。
- 選択行が内側の固定ヘッダーに隠れ得る→戻る際に実際のヘッダー下端と行上端から重なりを補正。
- Inspector内部で診断までスクロール済み→領域移動で見出しから再開し、対象IDを確認可能にする。

さらに親からの独立レビューを統合。構成指定で開く際は検討判断と比較中のみの条件も解除する。検索なしでは不要な索引構築をしない。手順表示と検索用ラベルを共通化。A/Bへ渡すラベルには実際の展開識別用ヘルパーを使う。

## 検証

別headless Chromeで現在のチェックアウトの `http://127.0.0.1:5187` に接続。終盤174秒局面から新規探索し、実エンジンが生成した5候補のうち3件を比較へ追加。fixture注入なし。

- 700×900の狭幅で3番目の行を選択→選択候補の検査→Tabで「一覧へ戻る」→Enter。戻ったフォーカスの完全IDと元の選択IDが一致。
- 横比較へ移動後のフォーカス先が比較領域であることを確認。
- 検索0件でも比較移動は有効、Inspector移動は無効。取り置きは維持。
- 1280×720で候補パネル863pxとscrollWidth863pxが一致。左右同時表示を維持。
- TypeScript検査成功。

スクリーンショット: `/tmp/candidate-navigation-narrow.png`、`/tmp/candidate-navigation-wide.png`。移動前後の時間短縮は計測していない。独立したショートカット体系や領域内の全文フォーカス履歴は費用に対して必要性が未確認なので採用しない。今回の領域移動自体には保存状態を増やしていない。

再訪の実操作では、Inspectorを最下部へスクロールした後でも移動操作で内部scrollTop=0になった。比較表から0件一覧へ戻った際は`.candidate-table`がフォーカスされ、1列668pxへ復帰。さらに一覧を最下部へスクロールしてから先頭選択行へ戻し、行上端279.84375pxと固定TH下端279.84375pxが一致し、見出しに隠れないことを確認した。THEAD自体は固定されていないため、補正量の計算には各THの実位置を使う。
