# 作戦詳細の得点解析

対象: `web/src/editors/strategy-detail/StrategyScore.tsx`、`score.ts`。担当 strategy_score。

## 既存機能と配置

既存の得点エディターは再生時刻の推移・内訳・範囲差分を表示できる。候補の内容を知る際には、最終点に開始局面の得点が含まれることと、得点変化時の実行動作を別途読む必要があった。専用詳細内では推移グラフを複製せず、開始・増加・減少・差引・終了を項目別に常設する。

- 内訳行は得点区分の識別と絞り込み。項目名を押すと同区分の変化を表示し、同じ操作で解除する。常設の項目選択でも操作可能。
- 変化時刻は再生位置への移動。赤・青の総得点を同時表示し、反転による双方の増減を確認できる。
- 同時刻の動作は選択した変化の文脈。同一 edge と時刻が一致する記録だけを表示し、機体付き再生位置へ移動する。個々の機体への得点寄与配分は行わない。
- 項目と増減は独立フィルタ。開始状態の点数を獲得点に算入しない。空条件を表示し解除できる。
- 表は局所スクロール、選択内容は直下に表示する。折り畳み・メモ・常設説明段落は置かず、既存の ? ヘルプを使う。

## 局所再検討

1. 既存得点エディターをコードレビュー。グラフ複製と機体別寄与推定を棄却し、区分別増減と動作への接続を実装。
2. 開始状態を再検討。100秒開始の試験で初期スカイ40点と途中の増加40点を分離。終了−開始の差引列を追加。
3. 同時完了の接続を再検討。同時刻でも異なるedgeを除外。blocked記録を完了動作として出さない。合計0でも区分間の変化を保持。
4. 絞り込み後の選択を再検討。非表示になった行の詳細を残さず先頭の可視行を表示。空・単一sampleの試験を追加。過去時刻を失敗原因とする表示は棄却。
5. 実際の探索エンジンで候補を生成し、全区分で開始＋増加＋減少＝終了、候補の最終得点との一致を検証。差引列と ? ヘルプの文言を再読し、得点寄与の断定を除去。

5件のテストと型検査通過。ローカルでの5巡はコード・データ検証であり、5巡の実画面レビューではない。追加の子委譲は同時実行枠が全て使用中のため実施せず。表示領域の狭幅・フォーカス・時刻連動は親の統合実操作へ引き継ぐ。

未採用案: 得点の機体別因果配分は記録不足。得点目標編集はこの読み取り解析の範囲外。CSV出力は既存得点エディターにあり重複追加しない。選択展開の得点増減から実行動作を確認する担当範囲を満たしたため局所実装を終了。
