# 候補の選択と編集中メモへの復帰

2026-10-15。担当範囲は候補集合から編集対象を見失わないこと。探索・評価モデルは変更しない。

## 観察から掘り下げた枝

- 絞り込み → 一覧外の比較候補: 件数だけは表示されるが、どれかを探すには複数条件を戻して手で探索する必要があった。対象一覧から直接復帰を採用。比較中全件を複製する常設パネルは不採用。
- メモ編集 → 他候補を選択 → 検索0件: 親のdraftsは残るが所在が表示されない。未保存件数と対象への移動を採用。保存は完全な本文・判断が見える既存編集領域で行い、抜粋だけを見た一括保存は追加しない。
- 復帰対象の一覧 → 同じ候補が複数構成に存在: run/idを維持。短いIDだけだと識別しにくいため、再評価で実際の建設・反転手順とメモ抜粋を追加した。架空の作戦名称は付けない。
- 下書き一覧 → 変更を戻した場合: 親辞書にキーが残っても保存内容と一致するものは未保存件数から除く。標準の未判定・空メモも同じ。対象消失時は移動不能な項目を表示しない。
- 検索 → なぜ候補が残ったか: 一致したフィールド名を行内に表示できる部品を追加。メモは保存済みのものだけを検索する現契約なので「保存済みメモ」と明示。未保存内容によって編集中の対象が突然消える検索は不採用。
- 選択候補 → フィルター外への移動: 現状は別の可視候補へfallbackする。復帰で元のkeyへ戻せるが、フィルター前の選択履歴を増やすことは保留。単なるフォーカス移動に履歴を作ると往復が曖昧になるため、別の専用履歴モデルが必要。

## 配置と状態

`CandidateRecovery.tsx`: 候補集合に従属する復帰領域。未保存や一覧外の比較がある場合だけ入口を置く。summaryで件数を常時読め、開けば対象・手順・未保存か比較中かを同時に確認できる。リストは上限高を持ち多数候補でもInspectorを押し下げ続けない。ボタンは対象への移動のみ。Escは閉じてsummaryへ戻る。統合側は一覧外なら条件を解除し、元の安定キーを選択する。メモ復帰なら編集欄へフォーカスを移し、通常復帰なら候補行へ移す。

`CandidateQueryMatch`: 検索結果の識別補助であり操作ではない。小さいテキストとして手順・IDの近くに置く。否定条件しかない検索は一致フィールドがないので追加表示しない。

## OSS参照

VS Code 1.95.3 の [OpenEditorsView](https://github.com/microsoft/vscode/blob/1.95.3/src/vs/workbench/contrib/files/browser/views/openEditorsView.ts) をソースで確認。`updateDirtyIndicator` とヘッダーの未保存件数、`onDidOpen` から `openEditor` への対象移動、安定IDでのリスト更新を参照した。未保存対象を作業文脈から見失わず、対象へ戻って編集する構造を採用。本アプリではファイルツリーやSave Allのまねはせず、候補の検討メモを既存Inspectorで保存する。VS Code実画面の操作確認はしていない。

## 検証と再評価

`recovery.test.ts` 2件で一覧外・重複ID/構成・消失対象・既定値・保存済み一致・判断だけ変更・メモ削除を確認。TypeScript検査成功。再評価でIDだけの復帰項目は見分けにくいため実手順を追加。

ブラウザMCPで独立newPageを試みたが既存profile使用中で起動拒否。親担当の実画面検証では「下書きを再訪して比較」を入力 → 検索0件 → 復帰項目選択 → 5/5件に復帰し、同じ本文とtextareaへのフォーカスを確認した。Esc・狭幅は次の独立レビュー担当が継続する。保存は既存onReviewChange経由。下書き自体はフィルターと候補間移動では保持されるが、エディタunmount/reloadまでの永続保存はこの部品では実装していない。
