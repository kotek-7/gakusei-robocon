# 再生中の経路と選択状態

担当: context_contract。対象は共有状態、URL、履歴、比較の保存。画面やコマンドの接続は別担当。

## 配置を支える状態の区別

参考PDFの Selection context と Pinned inspector は、同じ選択を全領域へ流す場合と、表示元を固定する場合を分けている。本アプリでは一覧の選択、詳細パネルの作戦選択、3Dで再生する経路が独立している。再生元を一覧の選択から推測せず、明示的に開いた経路へ付ける。

- `session.replay` は再生中の候補、構成、相手手順の出典。ロボット選択、時刻移動、ワークスペース切替では保持する。
- 局面を直接開く操作は由来を消す。検索・構成・経路が変わった状態に古い候補名を残さない。
- 比較A/Bはそれぞれ固定した経路に由来を持つ。現在の経路と混ぜない。旧保存データは由来なしとして読める。
- 履歴には構成とページ位置も含める。別構成へ移る直前の状態を原子的に保存する。
- 共有URLでは経路は一度だけ格納し、候補のメタデータを別のパラメータに置く。読み込み時に経路と結合する。現存候補への照合は表示側で行う。

## 巡回記録

1. 既存の状態と全変更入口を調査。単なるラベル追加は、手動局面へ移った後の誤表示につながるため不採用。共有の検証・破棄処理をstoreへ置いた。selectNodeへrun/offsetを渡し履歴を原子的に更新。
2. URLと比較保存の往復を検証。長いURLへpathを二重格納する案をやめ、既存pathパラメータから復元。比較A/Bの由来保存、旧データ互換、由来の破棄を検証。経路2000辺超はURL省略という既存上限を維持するが、アプリ内の由来にはその制限を適用しない。
3. 孫担当 `contract_review` が状態不変条件と相互操作を2巡レビュー。URLの時刻省略時に以前の時刻が残る問題、ページoffsetの持ち越しを修正。ナビゲーション中のhoverで遷移が取り消される指摘はnavigation担当へ転送。

局所検証: replayContext 4件、router 3件、workspace 4件の合計11テスト成功。共有UI全体の実画面検証は統合担当が実施する。操作用の状態機構が増えるため、独立したピン操作や新しい履歴UIは追加していない。

残件: 2000辺超の経路は共有URLに由来を含めない。長い経路の保存方式変更は今回の表示改善の範囲外。履歴、由来消去、比較復元の対象範囲を満たし、局所実装を終了する。
