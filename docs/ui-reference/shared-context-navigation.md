# 表示経路の由来と移動

対象は候補一覧からの3D表示、対応一覧、比較表、実行不可の時刻表示、作戦詳細、最高点候補、A/B割当。各入口で候補IDと具体的な展開IDを経路と一緒に渡す。一覧の選択変更では表示経路を更新しない。

## 配置と採否

参照根拠は [共通文脈のパターン調査](shared-context-patterns.md)。PDF p24 Reveal、p35 Selection truthとVS Codeの明示Revealを適用した。元候補への移動は共通入口内に置き、新しい常設ボタンは追加しない。`strategy.reveal` はレイアウトだけを切り替え、`strategy.inspect` は対象展開を読み込む。この違いにより、詳細を確かめる操作で再生位置が終局へ移動しない。

比較の割当は既存のA/B操作に由来を付加する。比較の固定元を現在の一覧選択から作り直す案は棄却した。手動局面選択は由来を消し、履歴は保存した由来を復元する。

## 巡回

1. 呼出箇所を調べ、候補一覧・比較表で候補IDが失われていたため、既存のonOpenとcommand引数に由来を追加した。`worst`のような可変の意味ではなく、開いた具体的な展開IDを保存する。
2. 非同期操作を再確認し、遅い候補読込が後から選んだ経路を上書きする競合と、比較割当中の探索切替を防いだ。構成変更もselectNodeと一括適用して旧履歴の構成を保つ。無関係な機体選択・比較状態の更新は経路読込を中止しない。
3. 共通入口からの移動を確認し、時刻・再生・対象選択を保つReveal専用操作へ分けた。対象の候補/展開が存在し、現在のnode/pathと一致する場合だけ実行できる。

## 検証と終了範囲

`coreNavigation.test.ts` で逆順の読込完了、途中の局面移動、途中の機体選択、比較割当中の探索切替、Revealによる再生状態保持を確認した。`replaySource.test.ts` と既存selectionテストで評価更新後も具体的展開が一致すること、同じ局面でも経路や裁定が異なる展開を区別することを確認した。

この担当は3巡、追加委譲なし。ブラウザーの候補選択・元候補への移動・A/B表示は統合担当へ検証を接続した。この記録単独ではブラウザー実操作済みとしない。対象の由来接続は全入口を網羅し、独立した新UIを追加する未処理案はない。
