# 再生・タイムライン

## イベントの種類と表示機体で移動先を絞る

状態: 実装済み

- レビュー所見: 動作帯には機体の表示切替があるが、イベントの前後移動は全機体・全種類を対象にしていた。「赤 BR の反転時刻を探す」ために関係のないイベントを何度も通過する。
- 参照: `docs/ui-reference/timeline-analysis.md` §1 #19 のイベント移動、§2 のルーラー、§3 のイベント分類。既存の密度を保ち、独立したイベント一覧パネルは増やさない。
- 採用: ヘッダーの「イベント」メニューで反転、設置、取得条件などを選択。イベント印と前後移動に同じ種類・機体条件を適用する。タイムライン内の ↑/↓ も同じコマンドに接続。
- 不採用: カスタムイベント分類。現在の分析イベントの固定種類で目的を満たし、利用者の分類管理は不要。
- 不採用: 全体の前後移動の挙動変更。別エディタの前後移動は全イベントを対象とする既存の用途を保つ。

### 表示機体とイベントの同期

状態: 飽和（今回の対象範囲）

- 機体が特定されたイベントはそのレーンの表示に従う。
- チーム単位の取得条件などは、そのチームのどちらかの機体が見えていれば表示する。
- 同時刻の複数イベントは1回の移動にまとめる。イベント印に各種類の説明は残す。
- レビュー: 全機体非表示、赤のみ、チーム単位イベント、同時刻の重複をテストした。現段階でさらに独立した設定は不要。

### 移動先がない場合

状態: 飽和（今回の対象範囲）

- 前後に該当イベントがなければ位置を維持し、「次の表示イベントはありません」などを通知する。
- 最後から最初への自動循環は不採用。反転や設置の時系列を調べる際、時刻が意図せず戻るため。

## 区間解析を独立領域にする（2026-10-15）

1. 確認: 動作帯とイベント移動はあるが、一定区間で各機体がどれだけ待ったかを比べられない。
2. OSS確認: [Blender space_time.py](https://github.com/blender/blender/blob/main/scripts/startup/bl_ui/space_time.py) の `playback_controls` はプレビュー範囲の開始・終了を直接編集し、`TIME_MT_view` は範囲へ表示を合わせる。`show_keys_from_selected_only` は選択対象に表示を絞る。コードを2026-10-15に確認した。
3. 実装: 区間開始・終了、機体別の動作数・動作秒・待機秒を追加。区間は共有する再生範囲を使い、得点と動作履歴も同じ範囲で調べられる。
4. 子機能を再評価: 待機合計だけでは該当動作に戻れないため「最長待機へ」を追加。範囲端にかかる動作は重複部分だけを計上する。経路外の時間を待機とみなさない。
5. 配置を再評価: 集計表をタイムライン内に置くと動作帯の高さを奪う。独立した「区間解析」エディタへ分離し、同じワークスペース内のタイムラインを「区間に拡大」で連動させる。追加の集計列を置ける領域を確保した。

自動の機体性能評価や「最適稼働率」は不採用。観測した経路の待機には戦略上必要な待機も含まれ、少ないほど良いとは言えない。計算結果の動作編集も不採用。

検証: 純関数テストで端の切詰め、別機体の除外、wait/delayの集計、経路外と境界の除外を確認。最長待機への移動と範囲編集のブラウザ確認は統合時に実施する。

### 区間解析のコマンド連携

区間への拡大は `interval.fit`、各機体の最長待機への移動は `interval.longestWait0`〜`3` に登録。パネルボタン・右クリック・コマンドパレット・キー割当てから同じ操作を呼び出す。範囲解除は既存の `play.clearRange` に統一した。非同期で経路を取得中に選択が変わった場合は移動しない。

## 再巡回: 動作内訳から実区間へ（2026-10-15）

過去の「飽和」は再評価した。最長待機への移動だけでは、移動・設置・待機の配分や二番目以降の待機を調べられない。

- 利用タスク: BRの待機を時刻順に確認し、一区間に絞って得点・3D・履歴と照合する。
- OSS参照: Kdenlive `7a3a84a656b0840fd6e0f6cd755b69cb80cf5cbb` の `src/kdenliveui.rc`、`select_timeline_zone` と `current_clip` メニュー。選択対象から区間操作へ接続する構造をソースで確認。
- 第1巡: 区間内の動作種別ごとに件数・合計秒を集計。全機体または一機体に限定する。区間端は切り詰め、未観測時間を待機としない。
- 第2巡: 集計だけでは各動作を特定できないため、種別名から時刻順の動作明細を開く。各行から開始時刻へ移動、またはその動作を共有解析区間へ設定する。時間移動と機体選択は同時に行う。
- 表示条件はエリア状態へ保存。`interval.filter` / `interval.inspectAction` を登録し、区間設定後の表示拡大は既存 `interval.fit` に接続。
- 不採用: 待機率による優劣判定。待機の戦術上の理由や未観測時間を区別できず、性能の良し悪しを結論できない。
- 検証: 区間切詰め、並行機体の加算、単機体絞込、並び順、元データ不変、不正区間を純関数テストで確認。ブラウザ統合検証は別記。
- anti-slop: 装飾カードを増やさず、集計表から明細表へ掘り下げる。複数機体の合計が実時間を超える理由のみ短く表示。
