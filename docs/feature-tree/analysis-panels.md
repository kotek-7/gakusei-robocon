# 解析パネル（得点・建設スポット・動作履歴・プロパティ）

## 時刻の整合 — 実装済み

対象タスク：候補の経路を戻し、再生時点の点数・建設状態と選択局面の状態を照合する。

レビュー所見：プロパティは選択局面の状態、得点と建設スポットは再生位置の状態。異なる時刻を表示する理由と移動手段が不足していた。さらに得点のムスティカ取得条件、スポットの反転・変化回数が経路全体の値で、再生位置の値と混在していた。

参照：`ui-reference/timeline-analysis.md` §5–7（リンクした選択、現在時刻の検査）、§1（時刻への移動）。

- 選択局面と再生位置を明記 — 実装済み
  - 異なる場合だけプロパティに再生位置を表示し、「局面の時刻へ移動」を出す。
  - 移動は `properties.seekNode` に登録。パレットからも実行可能。
  - 再帰：自動追従は打切り。行動分岐の編集対象が再生のたびに変わるのを避け、明示的な移動を維持する。
- 得点の現在値と経路末尾を分離 — 実装済み
  - 条件成立前は現在欄を「未成立」とし、末尾欄には経路上の成立時刻を残す。
  - 末尾の赤 / 青の順序と時刻を見出しに記載。
  - 集計上の注意は閉じた「集計条件」へ移した。
  - 再帰：個別の条件達成ビューは優先度で打切り。タイムラインのマーカーで時刻を調べられる。
- 建設スポットの現在までの集計 — 実装済み
  - 在庫の上に再生時刻を表示。反転と変化はその時刻以前だけを数える。
  - 履歴は経路全体を維持し、未来の変更へも移動できる。
  - 再帰：履歴の集約は打切り。現状は短い有限履歴で、各変更を選べることを優先する。

## 動作履歴の読み取り・移動 — 実装済み

レビュー所見：左側の細い領域で、表の自動列幅が長い行動名に引っ張られる。行クリックしかなく、キーボードで時刻へ移動できない。

参照：`ui-reference/timeline-analysis.md` §5–7（選択と時刻同期）、§13（リストのキーボード操作）。

- 狭い表での列幅 — 実装済み
  - 秒・機体・段階を固定幅、行動を残り幅で折り返す。
  - 再帰：列幅の手動調整は優先度で打切り。4列だけのため、行動の可読幅を確保するだけで対象タスクを満たす。
- キーボードで時刻へ移動 — 実装済み
  - 秒を通常のボタンとし、Tab → Enterで移動。行クリックも同じ `events.seek` コマンドを呼ぶ。
  - 再帰：セル編集は打切り。記録は計算結果であり編集対象ではない。

## 区間と選択対象から解析を掘り下げる（2026-10-15）

確認した不足: 動作履歴は機体別絞り込みがあるが、他領域の機体選択や再生範囲を利用できない。得点表は現在と末尾の比較のみで、指定区間で何が得点源になったかを読みにくい。

- 第1周: Blender `space_time.py` の選択対象のみ表示、プレビュー範囲の直接指定を参照。動作履歴へ「選択機体のみ」「再生範囲のみ」を追加。CSVは表示中の行だけを書き出す。
- 子機能の再評価: 選択がスポット等に変わった場合は空の表だけを残さず、機体選択を促す。CSVの各値は引用符をエスケープする。
- 第2周: 区間を指定したあと得点パネルを再確認。開始と終了の採点項目別増減、開始/終了への移動を追加。区間が経路外を含む場合は値を外挿しない。開始時点の点数を引く定義を表示する。
- 建設スポット: 配置図と一覧の両方を「空き」「アースのみ」「スカイあり」で絞り込める。子機能として一覧のスポット名をボタンにし、キーボードから履歴へ接続した。追加の色や装飾カードは不要と判断した。

参照: [Blender timeline UI source](https://github.com/blender/blender/blob/main/scripts/startup/bl_ui/space_time.py) の `TIME_MT_view`、`playback_controls`。ソースを2026-10-15に確認。Operate/craft-floorの標準テーブル・通常ボタン・折り畳みを使用し、説明は値の意味が変わる集計条件に限定した。

区間の得点差を純関数へ分離し、開始端の加点を除外すること、終了端の減点を含むこと、ゼロ幅区間、不正範囲・経路外の拒否をテストした。区間集計と合わせて5テスト成功。

## 再巡回: 同一区間で比較し、建設状態から区間を選ぶ（2026-10-15）

- A/B比較の不足: 末尾の得点と全経路の稼働秒では、同じ時間帯の違いを特定しづらい。共有解析区間を指定した場合、赤・青の得点増減と4機体の待機秒をA/B/B−Aで追加表示する。区間を全て観測できない経路は外挿せず「—」。開始・終了へ移動する操作を `compare.seekRange` に登録。
- 子機能の再評価: 建設スポットで状態変化を調べたあと、手入力せずにその状態が続いた時間帯を比較したい。履歴行に「次の変化まで N秒」を追加し、`spots.inspectChange` から共有区間・再生時刻・スポット選択・タイムライン拡大を連動させた。末尾行は観測経路の終了までとし、0秒の区間操作は表示しない。
- 参照: Kdenlive `7a3a84a656b0840fd6e0f6cd755b69cb80cf5cbb` の `src/kdenliveui.rc`、`select_timeline_zone` と `current_clip` の操作構造。対象から解析区間へ接続するパターンを採用。
- 不採用: 異なる相手手順の結果を勝率として表示すること。選んだ2経路の観測値比較という境界を維持。
- 検証: 区間得点の開始端除外・終了端包含・範囲外拒否テスト、および区間内訳テストを合わせて7件成功。ブラウザ確認は統合時に記録。
