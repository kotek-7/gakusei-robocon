# 探索・候補・比較

## 候補から2経路を比較する — 実装済み

2026-10-14。既定条件で探索を作成し、候補探索後に「得点と経路」を開いた。相手待機の310対0と、相手対応ありの230対485の経路を比較した。これは同一候補の異なる相手条件を使った操作検証であり、候補間の優劣の証明ではない。

参考：`docs/ui-reference/timeline-analysis.md` の A/B 比較・リンク、`vscode-kicad-freecad.md` の一覧からの操作。

### レビュー所見

- A/B設定は一度経路を開いて別のメニューを使う必要があった。
- 比較対象は画面を再読み込みすると失われた。保存形式にはA/B欄があったが、UIとの同期がなかった。
- 比較対象だけを設定すると、基準経路が未選択のためタイムラインが空だった。
- 探索範囲・未計算分岐の表示が、実行不可の応答内部だけに置かれていた。

### 採用した子機能

- 展開ごとの「比較Aに設定」「比較Bに設定」 — 実装済み。コマンド登録を経由。Aに設定した経路をタイムラインの基準にもする。Bだけを設定しても基準経路は変えない。
  - 再帰レビュー：相手条件を混同しない列見出し — 実装済み。構成・候補ID・相手手順を表示し、比較が選択した2経路の結果であることを明示。
  - 全候補を一括でA/Bに入れる — 打切り。2経路の比較目的に対し、選択結果が曖昧になる。
- 探索ごとの比較対象・ラベル保存 — 実装済み。再読み込み・探索切替時に復元。
  - 再帰レビュー：A/B連続操作とマーカー保存の競合 — 実装済み。探索単位の書き込みを直列化し、遅い復元が編集中の選択を上書きしない。
  - 共有URLへのA/B全文埋め込み — 打切り。探索データが別ブラウザには存在しないため、URLだけで共有完了と誤解させる。保存データの書き出しを利用する。
- 一覧からの探索範囲表示 — 実装済み。応答の成功・失敗を問わず開ける。
  - 再帰レビュー：残り時間の推定 — 打切り。分岐が増える探索で確かな推定値を出せない。
- A/B別々のタイムライン — 打切り（今回は優先度下位）。再生範囲・前後イベント・他の解析パネルまで含む再生元の統一設計が必要。現状は基準経路Aを共通操作の対象にする。

## 2026-10-15：相手手順を固定して候補を調べる

一覧を確認すると、各候補の最小点差は出せるが、同じ相手手順に対する経路を選び直すには各行の詳細を開いて探す必要があった。

参照した実装：Blender [space_outliner.py](https://github.com/blender/blender/blob/main/scripts/startup/bl_ui/space_outliner.py) の `OUTLINER_HT_header`、`OUTLINER_PT_filter`、`OUTLINER_PT_options_filter`。文字検索と対象種別・状態を別の操作として持ち、選択した条件を残したまま対象を絞る配置を採った。

1. 候補一覧に共通相手手順の選択と、共通比較あり・未比較あり・実行不可ありの状態絞り込みを追加した。指定手順の全裁定分岐を検査済みで、構成内の全候補に共通するものだけを点差計算に使う。構成を変えると手順指定を解除する。
2. 追加後の経路選択を見直すと、手順が固定できてもA/B設定には応答一覧を探す手間が残った。そのため最小点差の行から直接A/Bへ登録できるようにした。比較ラベルに構成・候補・実際の相手手順を残す。
3. 実行不可に絞った後は件数だけでは原因を調べられなかったため、応答内に時刻・機体・手順番号・理由の詳細を追加した。応答一覧も指定した相手手順と実行不可条件に従う。

全構成をまとめた優劣判定、自動ランキングの推奨マークは採用しない。構成ごとに共通手順が異なり、未検査分岐が残るため。最小点差を保証値へ読み替えない。

検証：共通相手に含まれない共有応答、個別対抗手探索の応答、指定外の相手を除外する回帰テストを追加した。未確認はnullのまま残す。ブラウザの最終操作確認は親タスクで行う。

## 2026-10-15：比較項目と計算履歴を掘り下げる

候補の条件固定からA/B比較へ進む操作をコードで追った。比較表には得点、取得条件、行動回数、機体の稼働時間が常に並び、目的の行を探す必要があった。

- 比較項目を得点・取得条件、行動回数、機体稼働時間で切り替え、項目名でも検索できるようにした。既存の差分のみ表示と併用でき、表示を戻す操作を付けた。
- 比較表を再確認すると、片側の経路が終わった後も末尾得点をその時刻の値として表示していた。現在時刻が経路の範囲外なら「—」とし、双方が含む再生範囲を表示した。末尾値の比較は別の行に残す。
- 計算履歴は更新ありのフィルターに加え、終了理由で絞れるようにした。絞った全履歴の合計時間・候補増・対応検査を表示し、その集合をJSON保存できるようにした。直近3回表示でも集計・保存は絞った全件が対象。
- 履歴を見て次の計算へ進む操作を再確認し、各回と同じ制限時間で保存済み探索を続けるボタンを追加した。過去状態の再実行ではなく、現在の保存地点からの継続であることを文言に明記した。

Blender Outlinerの状態フィルターと表示対象の切替を引き続き参照した。比較の対象分類と文字検索を別々に保ち、操作を戻せる配置にしている。自動残り時間推定は採らない。探索中に分岐が増えるため、過去の計算時間から完了時刻を算出できない。
