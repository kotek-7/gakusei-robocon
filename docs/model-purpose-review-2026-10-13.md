# 作戦探索という目的に対するモデルの過剰性レビュー

## 判定

現行モデルは、機体能力・スペックの違いによって有効な作戦と得点がどう変わるかを調べる目的に対して、操作履歴の区別が過剰である。探索順の改善より先に、状態・行動・試合展開・評価単位の定義を見直すべきである。

ただし「全探索」を既成作戦のカタログや人が選んだ少数の展開に戻す提案ではない。ルールから導く、意思決定に必要な抽象状態と操作の全探索を目指す。詳細な3D再生も維持するが、描画に必要な情報すべてを探索の分岐や状態同一性へ持ち込まない。

この文書はレビューと改訂案であり、新モデルは未実装。既存ルールの再認定も行っていない。

## 実測と追加確認

[実用性評価](practical-search-review-2026-10-13.md)では、180秒対象を約5分探索して16,367局面・41,852遷移を生成しても、終了局面は0対0の1つだけだった。終盤6秒を約1分探索しても、行動指定なら到達できる125対45を発見できなかった。探索順の問題はあるが、操作履歴全体を扱うモデルの大きさも問題である。

追加で `legal` を直接呼び、標準・全能力・積載3個のTRが各取得地点にいる状態を構成し、行動候補数を確認した。これは局所的な行動生成の検査であり、その局面への経路探索の計測ではない。

| 状態 | 生成される候補 | 判断上の問題 |
|---|---|---|
| 試合開始位置のTR | 待機5、リトライ1、移動1 | 開始位置から開始位置へ戻る操作も含まれる |
| アースブロック保管位置のTR | 取得275通り | 積み方の差と物体IDだけの差が混在する |
| スカイブロック取得位置のTR | 取得298通り | 1個12通り、2個66通り、3個220通り |

スカイブロックの初期12個は、現モデルでは同じ取得位置にあり、種類・所有者・色・搬送履歴も等しい。取得時間は物体IDや個別スロットによって変化しない。初期の取得候補は、物体の対称性を扱う抽象化によって「1個・2個・3個」にまとめる候補となる。ただし単独機体の選択をまとめるだけでは不十分であり、双方が同時に取る場合の競合・重複・在庫制約も保存しなければならない。全局面のIDを無条件に消すことはできない。

開始1秒の完了探索は全終了局面が0対0にもかかわらず81作戦に分類された。得点が同じこと自体は同一作戦の証明ではない。しかし現行分類は移動・リトライの開始を含む先頭3イベント群で切られており、採用技術の効果や得点への到達構造を比較する単位として適切か、根拠が弱い。

## 残すべき詳細と減らすべき区別

| 要素 | 判定 | 改訂案と残す制約 |
|---|---|---|
| L2進入・GND–L1の階段／スロープ能力 | 必須 | 採用技術による到達領域・経路・所要時間の差を残す |
| 機体別の並行動作、TR–BR受け渡し | 必須 | 運搬・建設の分担、積載数、同期条件を残す |
| 所要時間と終了時刻 | 必須 | 秒単位の時刻表現を維持。意思決定は意味のあるイベント境界を基本とする |
| タワーの位置・層・色、ムスティカ条件 | 必須 | 得点・到達可能性・競合・勝敗に影響する属性を残す |
| 個別ブロックの固定ID | 多くの場面で過剰 | 種類・所有・位置・支持構造・色・搬送加点状態など将来へ効く属性で交換可能性を判定 |
| 毎秒の任意リトライ | 基本探索には過剰の疑いが強い | 戦術的帰還や運搬解除として意味のあるリトライは残す。中断時刻の扱いを別途定義 |
| 任意の待機秒数の組合せ | 区別が過剰 | 相手到着、受け渡し可能化、資源解放、終了前の最終開始時刻などに基づく待機を検討 |
| 隣接通路を一つずつ選ぶ移動 | 判断地点のない区間では過剰 | 分岐・操作・競合のない連続区間をまとめる。階段／スロープの選択や競合地点は残す |
| 同じ局面へ至る全操作履歴の明示列挙 | 主探索では過剰 | 将来に効く情報を状態に、説明と再生の情報を経路に分離。分類に必要な履歴要約は保持 |
| 先頭3イベント群による作戦分類 | 判断用途との対応が弱い | 操作モデルの改訂後、資源・配置・到達領域の変化を表す構造で機械的分類を再検討 |
| 全局面の最善応答・混合方針保証 | 初期の探索目的には重い | 得点・成立条件・相手条件別結果を先に提供。閉じた範囲で完全性を確認できた場合に保証を追加 |

## 提案するモデルの境界

探索状態は、各機体の作業地点・保持資源・進行中操作の必要な状態、残り資源、各建設スポットの構成、得点に関係する搬送履歴、取得条件、時刻を中心とする。履歴依存の規則に必要な情報は省略しない。

行動は、ルールから成立条件・所要時間・資源変化を計算できる汎用操作とする。例は「許可された経路で作業地点へ移動」「同等なブロック群から条件を満たす個数を取得」「受け渡す」「指定スポットへ設置」「裏返す」。特定の得点順序や戦法を人があらかじめ登録する方式にはしない。

時刻を1秒単位で表すことと、1秒ごとに新しい判断を生成することを分離する。動作開始・接触・資源解放・動作完了・試合終了など、規則や相手の応答へ影響する境界を扱う。裏返し中に敵の得点が外れる現行挙動を維持するなら、操作開始と設置完了を一つの不可分な得点変化へ潰してはいけない。

双方の干渉がない操作を表面的な実行順だけで別展開にしない。一方、同じブロックの取得競合、タワー操作の排他、到着順が変わる場合は分ける。操作の独立性は同時実行時の制約も含めて判定する。

3Dは抽象経路から具体的な代表物体・移動軌道・動作時刻を復元する。どの実物IDを割り当てたかは再生用の対応として保持し、交換可能なIDの違いを作戦数へ持ち込まない。復元した経路が操作条件を満たすことを検査する。

## 変更の種類を混同しない

1. **意味を保つ縮約**：交換可能な物体の正規化、判断点のない区間の統合、独立操作の同値化など。将来の合法な選択・所要時間・競合結果・得点を保つ条件を確認し、小規模全列挙と照合する。
2. **探索対象の変更**：任意の秒でのリトライや待機を意味のある判断時点に制限する場合。一般に無損失とは言えない。消える展開と技術比較への影響を明記し、モデル版を分ける。今回のレビューだけで既存の許可行動を削除しない。
3. **集計単位の変更**：ID差や操作順差を同じ展開として数える場合。局面の統合だけなら経路の多重度を保持できるが、評価上も同一視するなら展開数・割合の意味が変わる。旧モデルの件数との単純比較は行わない。

## 「よい作戦」の評価もモデルの一部

展開グループ等重みの割合は、抽象化の仕方に依存する。ある物体IDの選択だけを細かく分ければ、その種類の展開の重みが増える。完了探索であっても、実大会で選ばれる確率が分かるわけではない。

評価単位の三層は維持する。

- 単一展開：両チームの最終得点、点差、勝敗、時刻、成立に必要な能力。
- 作戦：機械的な分類構造、含まれる結果の範囲・分布・件数、相手条件、未探索の有無。
- 判断構成：同じ初期局面・相手条件のもとで到達できる結果、能力追加／削除で生まれる／失われる展開、所要時間の閾値、必要能力の包含関係。

勝つ展開の割合は説明可能な集計単位を定義した上で補助指標として残す。保証値を出す場合は相手の行動集合を閉じているか、全分岐を調べたかを別に確認する。探索で発見した最高得点を、相手に対して保証できる得点と混同しない。

作戦の意味的な命名やAIによる推奨は追加しない。粗密調整や任意の枝刈り条件を利用者へ押し付けず、固定モデルを小さな検証例で評価して改訂する。

## 次の実装前に決めること

最初に「同じ展開とみなす条件」「判断を生成するイベント」「リトライと待機を含める境界」「標準の比較指標」を短い仕様にする。探索器の高速化を先行させない。

次に小規模な参照問題で、物体IDの交換、受け渡し、階段／スロープ、反転2／4／8秒、相手との同時取得、試合終了をまたぐ操作について、縮約前後の得点・到達性・競合結果を照合する。履歴を同一視する場合は対応関係と多重度を別に検査する。

その後、今回の終盤6秒・反転6構成・試合全体の計測を繰り返す。終了経路を発見できるだけでなく、明示した抽象モデルの範囲を完了し、能力を変えた比較が再現可能であることを評価する。縮約後でも180秒の全構成が必ず実用時間で完了するとは約束しない。
