## ルールから直接導ける作戦上の性質

1. **得点差で評価する。** L1反転は自分+40・相手-40で差が80変わる。L2反転は差が160変わる。Earthの得点は移らない（8.2–8.4）。
2. **資格獲得と終盤の塔保持は別の目的。** 自色の完成塔2本、うち共有区域に1本を満たした資格は永続する（3.6.1–2）。2本を別々の時点で一度ずつ保有しただけでは解除しない解釈で実装。
3. **Mustikaは取得競争と最終得点の両方に効く。** 取得は資格獲得後（4.5.1）。正しく奉納し終了時に安定していれば250点（8.5）。先に取れば相手の機会も失わせるが、これは相手が取得できた反実仮想との比較であり常に500点差の価値があるわけではない。
4. **奉納後も競技は続く。** 180秒で判定し、一発勝利はない（4.2.3、9.1）。資格→Mustika→終盤反転の複合作戦を候補に含める。
5. **搬送と建設を並行させる。** TR3個、BR2個上限（3.4、4.4）。塔1本の材料は2E+1Sなので、BRが1往復ですべて運ぶモデルにしてはいけない。
6. **相手の土台を使える。** 混成塔とSky反転を許可し、Earthは設置者に帰属させる（3.5.5–8、8.3–4）。共有エリアを完成塔の個数だけで表すと、この選択を失う。
7. **妨害による防衛を合法手段に含めない。** 進路封鎖や操作干渉は6.6で禁止。塔を取られないようBRを居座らせる戦略を正当化しない。
8. **ロボット間通信は禁止。** 11.10。シミュレータの完全な盤面情報をそのまま実機へ渡せるわけではない。固定手順、時計、各ロボット自身のセンシングで実装可能かを別途評価する。

## 行動と抽象化

| 行動 | 前提 | 結果 |
|---|---|---|
| TR搬送 | E/S合計1〜3、在庫あり | 受渡しへ追加、5点/個 |
| TR Mustika回収 | 資格あり、地上柱に存在 | 受渡しへ。Mustika搬送に5点は与えない |
| BR初回昇段 | 開始直後の固定動作 | L1作業を開始可能に |
| BR Earth設置 | 受渡し在庫、空き下段/中段、最大2個 | 設置者を記録 |
| BR Sky設置 | Earth2段、受渡しにSkyあり | 自色完成塔に |
| BR Sky反転 | 相手色の完成塔 | Earth帰属は変えず自色に |
| BR Mustika奉納 | 自チーム受渡しにMustikaあり | 中央柱へ |
| 待機 | 常時 | 1秒経過 |

実装する各行動は**経路や把持をまとめたマクロ行動**。現実の全合法操作を網羅していない。各マクロの資源は開始時に予約し、地点の操作を直列化する。同時刻の競合には赤優先/青優先を別シナリオとして適用する。優先権を公式ルールと解釈しない。選択は同一スナップショットで行い、相手が今選んだ行動を見てから選び直すことはできない。

所要時間は地点区分だけで決まり、前の位置からの距離は持たない。転倒、衝突回避、ロボット寸法・姿勢、壁越し操作、階段の実現性、積み重ね途中の支持、受渡しエリアの容量、視野・認識遅延は含まない。反転中のSkyは保持物として採点から除くが、接近と把持の時点を分けていない。このため終了直前の反転評価は特に楽観的になり得る。

省略した合法候補には、任意のEarth積み直し、Sky撤去・他地点への移設、SkyとEarthのBR混載、落下物回収、戦術的リトライ、初期Earth配置・開始ゾーンの選択、完了時刻が180秒を超える妨害的な保持開始がある。作戦総当たりでは期限内に完了する行動のみ選ぶ。短時間の状態全探索では期限をまたぐ行動も扱う。

搬送済み物体の反復搬送による得点稼ぎは認めないモデル。個体を地上へ戻す操作を実装していないので、重複加点は生じない。すでに奉納したMustikaの相手による取り外しは許可も禁止も明文が見つからないため、不可と仮定。FAQ確認事項とする。

## 探索の意味

### 180秒の作戦総当たり

建設優先順位3!通り × Mustikaなし/通常順序/資格優先の3通り × 反転開始3通り × 搬送方針2通り = 108個の状態依存方策。すべての組合せを、3つの同速条件と2つの速度差条件、同時競合の優先順2通りで対戦させる。`manifest.json`に全候補を保存する。108という数は競技の全戦略数ではない。

最悪得点差を主評価にするが、相手も108候補に限定される。全相手への勝利保証ではない。候補群平均を実大会の相手分布に対する期待値や勝率と呼ばない。

成功率試行は上位5候補・特定相手・40 seed×優先順2通りの有限サンプル。成功率は搬送・設置・反転・Mustikaのマクロ1回あたりで、2個同時設置の失敗相関もまとめる。初回昇段と復帰自体は必ず成功する仮定。失敗動作は保持物を維持して復帰時間後に再試行、Mustikaのみ地上柱へ戻す。実際の落下・破損・リトライ・回収とは異なる。

### 局面の完全探索

`search.exhaustive`は、与えた初期局面・時間範囲・有効ロボット・決定論的性能・優先順の下で、実装済み行動の全分岐を列挙する。同じ状態は統合するため、列挙数は試合の履歴数ではない。`complete=true`のときだけ、その範囲の到達状態を全探索済みと呼べる。

`max_states`で打ち切った場合は必ず`complete=false`にする。到達可能性の分析とゲーム理論上の最適方策は異なる。相手の悪手によって到達した勝ち局面が存在しても、勝利を保証しない。

## 必要性能の測り方

速度を単一の走行速度だけで置かず、次をそれぞれ測定・スイープする。

- TR: E3個、S3個、E2+S1の収集から受渡し完了まで。ランプ昇降、把持、放しを含む。
- BR: 初回昇段、E1/E2設置、Sky設置、反転、各地点間の遷移時間、L2昇降。
- Mustika: 資格判定からTR取得・受渡し、BR奉納まで。
- 各動作: 成功率、失敗モード、復帰時間分布。平均だけでなく遅い側の分位点を取る。
- 観測: 相手の動き、塔の上面色、バッファ在庫、資格成立を各機体が通信なしで知れるか。

仮定上の性能差を、未製作のロボットに対する実現可能性の証明にしない。

## 次の拡張と完了判定

1. 公式FAQ・国内ルールで上の台帳を確定する。
2. 経路グラフ・機体位置・運搬物の個体ID・観測範囲を状態に加える。開始予約を実際の到着/把持/解放イベントに分割する。
3. 任意の合法操作を追加し、失敗を確率分岐として表現する。有限性を保つ時間刻みと最小動作時間を明示する。
4. 同値状態の統合、上下界、支配関係による枝刈りを証明したうえで、全試合の探索へ広げる。枝刈りや方策制限により失う戦略を記録する。
5. 同時手番の確率ゲームとして解き、勝敗・得点差・リスクの目的を分け、反例試合と性能境界を保存する。
6. 実測性能と実機の観測条件に合わせて再評価する。

現状はルールの主要部分を動かせる探索基盤と初回の有限実験。競技全体の全展開・全戦略の探索完了や、実機で有効な作戦の確定には達していない。

## 初回実験の方策改善と厳密解

Mustikaを狙うM1方策には通常順序のQ0と資格取得優先のQ1を用意する。Q1は通常の建設順序より資格取得を優先する。自陣の完成塔を1本保有し共有塔がない場合、次の建設対象を共有に絞る。相手塔を反転すれば直ちに資格が得られる場合、反転開始時刻の設定にかかわらず実行する。これはルールそのものではなく、比較する方策の定義。

`game.solve`は小さな完全観測・同時行動ゲームを全分岐展開し、各局面の利得行列を線形計画で解く。混合戦略を許し、赤の期待得点差の最大最小値を計算する。最大状態数を超えれば`complete=false`を返し、最適値を出さない。浮動小数点計算には許容誤差がある。方策は相手の今回の選択を見る前に決めるが、過去の行動と実行中タスクを観測できる仮定。

例題では赤85点・青310点から開始し、赤が勝つ終端状態も到達可能である。しかし同じ局面のゲームの値は-65点。相手も最善に行動する場合、到達可能な勝ち状態を選んで実現できるわけではない。この違いが、単独の最高得点探索だけでは足りない理由となる。

### 有限候補群の混合戦略

`portfolio`は全対戦表を108行×216列の利得行列として解く。列は相手108方策×競合優先順2通り。自軍の作戦選択の確率分布を線形計画で最適化する。期待得点差と勝利指標を別々に最適化するため、両者の混合比は一致するとは限らない。勝利指標では審判判断未解決を非勝利として扱う。

相手が自軍の分布を知っていても抽選結果を見る前に方策を選ぶ、という有限戦略ゲームの値である。相手の任意の適応戦略を網羅した解ではない。表の欠損・重複があれば計算を拒否する。
