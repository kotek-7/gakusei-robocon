# NHK学生ロボコン2027 作戦探索

機体能力と数値スペックの組合せから、行動・局面・試合展開を探索するブラウザアプリです。条件編集、候補探索、相手手順との比較、詳細な全探索、評価、3D再生、保存をブラウザ内で行います。競技ルールはABUロボコン2027と同一と仮定し、用語は手元の日本語参考訳（非公式）に合わせています。

## 開発・配信

開発・ビルドにNode.js 22.12以上が必要です。利用者にNode.jsやPythonのインストール、計算サーバーの起動は不要です。

```sh
cd web
npm ci
npm run dev
```

配信用ファイルは次のコマンドで生成します。

```sh
cd web
npm run build
npm run preview
```

`web/dist/` 全体を静的ホスティングへ配置します。HTTPSで配信してください。開発時はlocalhostでも動作します。専用API、データベースサーバー、CDNへの外部依存はありません。HiGHSのWebAssemblyファイルもビルドに含まれます。サブディレクトリ配信に対応します。HTMLを `file://` で直接開く方式ではありません。

## 使い方

画面はワークスペース（上部のタブ）とエディタ領域で構成する。

| ワークスペース | 主な領域 |
|---|---|
| 条件 | 条件エディタ、モデル・前提 |
| 探索 | 作戦候補／計算と進捗のタブ、3D、得点／プロパティ |
| 試合解析 | 中央に3Dビュー、下にタイムライン、左にアウトライナー／動作履歴、右にプロパティ／得点／建設スポット |
| 状態グラフ | 状態遷移グラフ、3D、プロパティ |
| 比較 | 2つの経路をA/Bの3Dで並べ、差分表 |
| 評価 | 評価・比較／計算と進捗のタブ、3D、得点 |
| 検討記録 | 保存した経路・時刻と判断メモ、3D、タイムライン |
| 区間解析 | 機体別の動作・待機時間、区間得点差、3D、タイムライン |

1. 「条件」で能力候補と数値を選び、「この条件で探索を作成」を押す。
2. 「探索」の作業切替バー右側で探索時間を選び、「候補を探す」（F5）で候補を探索する。
3. 候補の経路を開くと、その局面までの経路を3D・タイムライン・得点で再生できる。Spaceで再生、J/K/Lで逆再生・停止・順再生、←→でコマ送り、↑↓でイベント単位に移動する。
4. 「評価を計算」（F6）で構成・作戦・展開を集計する。完全探索済みの構成では、HiGHSのWasm版による線形計画で勝利確率の保証範囲を計算する。

その他の操作は次のとおり。

- コマンドパレット（Ctrl+Shift+P / F3）から操作を分類で絞って検索できる。頻用操作を固定すると常設バーから実行でき、右クリックで固定を解除できる。
- 移動（Ctrl+P）では局面ID、時刻（`:73.5`）、候補、マーカーへ移動できる。
- 補助領域はタブで切り替える。タブの矢印キーで表示を移動でき、配置メニューの「このタブを隣に分離」で同時表示できる。
- 候補表で行を選び、隣の詳細から相手の展開、3D再生、比較A/Bを操作する。選択と絞り込みはタブを往復しても残る。
- プロパティは選択した機体・物体・建設スポットの再生時刻の情報を表示する。「局面」で選択局面の情報へ戻る。
- 各領域は右クリックで操作を選べる。ヘッダーの種類名をクリックすると、表示するエディタを切り替えられる。
- 設定（Ctrl+,）では表示・操作・計算の既定値とキー割当てを変更できる。
- 表示状態はURLに残る。「この表示へのリンクをコピー」で同じ選択と時刻を開き直せる。
- 「検討」メニューから経路・時刻・範囲を記録し、理由と判断を残せる。記録は検索・抽出してA/B比較に戻せる。
- 「解析」メニューの区間解析では、指定区間の待機時間と得点増減を照合できる。
- 700px以下の画面では領域切替バーから一つずつ全幅で表示する。

繰り返し検討するときは、各領域の次の操作を使える。

- 条件差分：編集開始時からの変更を確認し、項目ごと・表示範囲ごとに戻す。評価では比較対象との条件差分を確認する。
- 区間解析：機体・動作別の内訳から個々の動作へ進み、その時間帯を再生・比較する。
- 局面差分：プロパティで直前の局面を選び、得点・物体・機体の変化を確認する。
- 検討記録：時刻や判断で並べ替え、選択局面で絞り、複製・JSON保存する。

- 条件：数値候補の一括選択、取り消し・やり直し、項目検索、変更した項目だけの表示と復元。数値そのものは両チーム共通、候補の選択はチーム別。
- 候補・比較：手順やIDで検索、点差や未比較数で並び替え、共通手順での最小点差経路を直接表示。A/B比較は差のある項目だけを表示でき、点差の差が変わる時刻へ移動できる。
- 作戦候補：比較用のチェックと検査する行の選択を分け、一覧と横比較を同時表示。同一構成・共通相手手順ごとに最小点差と裁定幅を照合し、選んだ裁定を3D・A/Bへ送れる。差のある相手や赤／青の実行不可で絞り込める。
- 作戦詳細：候補の「作戦を詳しく見る」から、TR・BRの固定指示、資材条件、実行記録、得点の増減を確認。時刻や不成立の手順から同じ展開の3Dへ移動できる。
- [候補の追加探索・解析](docs/candidate-additional-analysis.md)：候補を指定して相手探索・既知手順の検査を続行。実行履歴から追加展開を辿り、相手別の点差幅や不成立指示を解析できる。
- 候補の表示条件と比較対象を探索と一緒に保存。検索は空白AND、引用句、除外、`手順:`・`理由:`・`ID:`に対応。一覧外の比較候補から元の対象へ戻れる。
- 候補の根拠：相手の展開を絞り、赤・青それぞれの得点増減、完了記録の同時性、相手待機から最初に異なる赤の完了組を確認。実行不可の記録から該当時刻・機体を3Dで開ける。
- 試合解析：動作履歴の表示対象、得点変化、選択スポットの変化を前後へたどる。アウトライナーは折り畳んだ階層も検索し、矢印キーで移動できる。
- 状態グラフ：領域の幅へ自動で合わせる。プロパティでは行動名や局面IDを複数語で絞り込める。
- 計算と進捗：履歴から候補・得点が更新された回だけを抽出。モデル・前提では用語、定義、ルール解釈を検索できる。

## 保存と再開

探索はこのブラウザのIndexedDBへ、計算中はおおむね1秒ごとと停止・完了時に自動保存します。局面、全遷移、未探索分岐のカーソル、候補、相手手順、集計をまとめて確定します。

タブを閉じる・再読み込みする・端末をスリープさせると、計算は継続できません。開き直して「候補探索を続ける」または「全探索を続ける」を押すと、最後の保存地点から再開します。保存前の直近の計算は失われる場合があります。評価計算が中断した場合は、前の確定結果を残し、評価を最初から再計算します。

- 「バックアップを書き出す」（Ctrl+S）で、探索全体と注釈（マーカー・保存した視点・ピン）をJSONファイルに保存します。「バックアップを読み込む」（Ctrl+O）で別のブラウザにも復元できます。
- 保存先はブラウザ・端末・サイトのURLごとに分かれます。サイトデータの削除やブラウザの容量管理で消える可能性があるため、大切な結果はファイルにも書き出してください。
- 同じサイトの複数タブが保存内容を上書きしないよう、計算画面は1タブで開きます。
- メモリ使用量を抑えるため、1探索の局面50,000件、遷移150,000件、候補探索状態50,000件を目安に自動中断します。条件を絞って新しい探索を作成してください。中断を探索完了とは表示しません。

画面配置は `robocon.layout.v3`。旧配置は引き継がず、新しいドック配置で開始する。探索・注釈の保存には影響しない。

保存形式は `browser-2`、バックアップは `robocon-browser` v2、競技モデルは `browser-1`。以前のブラウザ版（保存形式 `browser-1`）と旧Python版の保存データには、互換性も移行処理もありません。

## 探索結果の意味

位置・経路・動作時間を有限化したモデルです。動作成功を前提とし、接触力学、転倒、把持軌道、通信なしで実行できるかは検証しません。競合の優先順など、未確定の解釈は設定に分離しています。

候補探索は、各ロボットが動作を終えるたびに取得個数・混載・受け渡し・建設先などを選びます。移動は最短経路、待機時刻は限定しています。相手の手順を共有し、同じ構成の候補で全裁定分岐まで検査できた共通手順に限って比較点差を表示します。候補は経路の代表例であり、全経路一覧や最適性の保証ではありません。

詳細な全探索では、選択した全構成の全分岐が処理できた場合だけ「探索完了」とします。未探索・打切りを到達不能や0勝とは扱いません。180秒より短い時間窓は、その時点の局面評価です。180秒の全探索が実用時間やブラウザの容量内で完了する保証はありません。

## 本番環境とCD

公開先は https://robocon2027-lab.kotek7.com です。Cloudflare Workers Static Assetsで配信します。

`.github/workflows/deploy.yml` は、`main` へのpushでテスト・型検査・ビルドを実行し、成功した成果物を本番へデプロイします。Pull Requestでは検証だけを行います。デプロイ後はHTTPSの応答を確認します。同じブランチの実行は直列化しています。

GitHubのリポジトリ変数 `CLOUDFLARE_ACCOUNT_ID` と、production環境のSecret `CLOUDFLARE_API_TOKEN` を使います。トークンには対象アカウントのWorkers Scripts編集、kotek7.comのZone読み取り・Workers Routes編集権限が必要です。認証情報はコードに保存しません。

再デプロイはGitHub Actionsの「Validate and deploy」をmainに対して実行します。以前の版へ戻すときは対象変更をrevertしてmainにpushします。Wranglerの設定は `web/wrangler.jsonc` です。
