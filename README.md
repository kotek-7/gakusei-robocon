# NHK学生ロボコン2027 作戦探索

機体能力と数値スペックの組合せから、行動・局面・試合展開を探索するブラウザアプリです。条件編集、候補探索、相手手順との比較、詳細な全探索、評価、3D再生、保存をブラウザ内で行います。競技ルールはABUロボコン2027と同一と仮定し、用語は手元の日本語参考訳（非公式）に合わせています。

## 開発・配信

開発・ビルドにNode.js 22.12以上が必要です。利用者にNode.jsやPythonのインストール、計算サーバーの起動は不要です。

```sh
cd web
npm ci
npm run dev
```

配信用ファイルは次のコマンドで生成します。

```sh
cd web
npm run build
npm run preview
```

`web/dist/` 全体を静的ホスティングへ配置します。HTTPSで配信してください。開発時はlocalhostでも動作します。専用API、データベースサーバー、CDNへの外部依存はありません。HiGHSのWebAssemblyファイルもビルドに含まれます。サブディレクトリ配信に対応します。HTMLを `file://` で直接開く方式ではありません。

## 使い方

画面はワークスペース（上部のタブ）とエディタ領域で構成する。

| ワークスペース | 主な領域 |
|---|---|
| 条件 | 条件エディタ、モデル・前提 |
| 探索 | 作戦候補、計算と進捗、3D、得点 |
| 試合解析 | 中央に3Dビュー、下にタイムライン、左にアウトライナーと動作履歴、右にプロパティと得点 |
| 状態グラフ | 状態遷移グラフ、3D、プロパティ |
| 比較 | 2つの経路をA/Bの3Dで並べ、差分表 |
| 評価 | 評価・比較、計算と進捗 |

1. 「条件」で能力候補と数値を選び、「この条件で探索を作成」を押す。
2. 上部右の探索時間を選び、「候補を探す」（F5）で候補を探索する。
3. 候補の経路を開くと、その局面までの経路を3D・タイムライン・得点で再生できる。Spaceで再生、J/K/Lで逆再生・停止・順再生、←→でコマ送り、↑↓でイベント単位に移動する。
4. 「評価を計算」（F6）で構成・作戦・展開を集計する。完全探索済みの構成では、HiGHSのWasm版による線形計画で勝利確率の保証範囲を計算する。

その他の操作は次のとおり。

- コマンドパレット（Ctrl+Shift+P / F3）から全操作を検索できる。
- 移動（Ctrl+P）では局面ID、時刻（`:73.5`）、候補、マーカーへ移動できる。
- 各領域は右クリックで操作を選べる。ヘッダーの種類名をクリックすると、表示するエディタを切り替えられる。
- 設定（Ctrl+,）では表示・操作・計算の既定値とキー割当てを変更できる。
- 表示状態はURLに残る。「この表示へのリンクをコピー」で同じ選択と時刻を開き直せる。

## 保存と再開

探索はこのブラウザのIndexedDBへ、計算中はおおむね1秒ごとと停止・完了時に自動保存します。局面、全遷移、未探索分岐のカーソル、候補、相手手順、集計をまとめて確定します。

タブを閉じる・再読み込みする・端末をスリープさせると、計算は継続できません。開き直して「候補探索を続ける」または「全探索を続ける」を押すと、最後の保存地点から再開します。保存前の直近の計算は失われる場合があります。評価計算が中断した場合は、前の確定結果を残し、評価を最初から再計算します。

- 「バックアップを書き出す」（Ctrl+S）で、探索全体と注釈（マーカー・保存した視点・ピン）をJSONファイルに保存します。「バックアップを読み込む」（Ctrl+O）で別のブラウザにも復元できます。
- 保存先はブラウザ・端末・サイトのURLごとに分かれます。サイトデータの削除やブラウザの容量管理で消える可能性があるため、大切な結果はファイルにも書き出してください。
- 同じサイトの複数タブが保存内容を上書きしないよう、計算画面は1タブで開きます。
- メモリ使用量を抑えるため、1探索の局面50,000件、遷移150,000件、候補探索状態50,000件を目安に自動中断します。条件を絞って新しい探索を作成してください。中断を探索完了とは表示しません。

保存形式は `browser-2`、バックアップは `robocon-browser` v2、競技モデルは `browser-1`。以前のブラウザ版（保存形式 `browser-1`）と旧Python版の保存データには、互換性も移行処理もありません。

## 探索結果の意味

位置・経路・動作時間を有限化したモデルです。動作成功を前提とし、接触力学、転倒、把持軌道、通信なしで実行できるかは検証しません。競合の優先順など、未確定の解釈は設定に分離しています。

候補探索は、各ロボットが動作を終えるたびに取得個数・混載・受け渡し・建設先などを選びます。移動は最短経路、待機時刻は限定しています。相手の手順を共有し、同じ構成の候補で全裁定分岐まで検査できた共通手順に限って比較点差を表示します。候補は経路の代表例であり、全経路一覧や最適性の保証ではありません。

詳細な全探索では、選択した全構成の全分岐が処理できた場合だけ「探索完了」とします。未探索・打切りを到達不能や0勝とは扱いません。180秒より短い時間窓は、その時点の局面評価です。180秒の全探索が実用時間やブラウザの容量内で完了する保証はありません。
