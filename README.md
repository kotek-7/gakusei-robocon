# NHK学生ロボコン2027 作戦探索

NHK学生ロボコン2027の作戦検討用。競技ルールはABUロボコン2027と同一と仮定します。用語は手元の日本語参考訳（非公式）に合わせています。

機体能力と数値スペックの組合せから、選べる行動・局面・試合展開を生成するローカルの探索アプリです。固定作戦のカタログ、旧Web計算エンジン、Pythonのマクロ実験は廃止しました。過去の実装と結果はGit履歴に残っています。

## 起動

Python 3.10以上、Node.js 22.12以上が必要です。

```sh
python3 -m pip install -r requirements.txt
cd web
npm ci
npm run build
cd ..
python3 -m explorer
```

[アプリを開く](http://127.0.0.1:4174)。探索は `.explorer-resource-events-2/` のSQLiteに自動保存されます。ブラウザを閉じても、Pythonプロセスが動いていれば計算は継続します。プロセスを再起動した場合は「探索を続ける」で保存済みの分岐から再開します。ローカルの127.0.0.1にのみバインドします。

開発時はPythonを起動した状態で `web` 内の `npm run dev` を使います。ViteはAPIを4174番へプロキシします。

## 使い方

1. 赤青の能力候補と、項目別の速い／標準／遅いを選択します。複数選択は独立に組み合わせます。数値は仮定として編集できます。
2. 試合開始・終盤の検証局面、または保存した局面JSONを選びます。動作中のjobを含む局面の初期条件への読み込みは受け付けません。
3. ルール解釈と初期配置を設定し、探索を作成します。
4. 計算上限を指定して探索します。途中でも局面を選び、選べる行動を直接選んで分岐を計算できます。他の選択肢は未探索として残ります。
5. グラフのノード・エッジを選び、経路を3Dで再生します。複数の入辺は保持され、別の履歴を選べます。
6. 「評価を計算」で構成・作戦・展開の集計を生成します。別の保存済み探索を比較対象にできます。

グラフは100局面ずつ表示します。範囲外の遷移は詳細の一覧から移動できます。ブラウザ内に全データを一括描画しません。JSONの書出しは調査用で、常用の保存・再開はSQLiteが担当します。

## 探索の意味

位置・経路・初期配置、操作と時間を有限化したモデルです。時刻は1秒単位で記録し、次の動作完了・試合終了まで進めます。操作成功を前提とし、動作中の任意リトライや時刻指定の待機は探索しません。同じ属性・積み方の物体は個数と属性で選びます。共有在庫は接触時に割り当て、不足する場合は競合結果を分岐します。機体の接触力学、転倒、把持軌道、通信なしで実行できるかは検証しません。未確定のルール解釈は設定に分離しています。

「探索完了」は選択した全構成とモデル内の全分岐の処理完了を意味します。打ち切りを到達不能・0勝と扱いません。180秒より短い終了時刻では、その時点の状態評価であり試合の最終勝敗ではありません。180秒の全構成が実用時間内に完了する保証はありません。

作戦は物体操作イベント（取得・受け渡し・建設・反転など）の先頭3組から分類した群です。分類では移動・リトライと物体IDの違いを除き、種類・個数を使います。詳細な移動と時刻は各試合展開に残ります。分類版と固定切断基準を保存します。分類のIDに解釈上の作戦名を付けません。集計は展開グループを等重み、群内の厳密展開も等重みとし、経路単位の集計を併記します。実大会の勝率ではありません。履歴集計も上限で打ち切る場合は未完了表示になります。

探索完了した構成では、同時行動の混合方針を許した線形計画で赤の勝ち保証を計算します。不確定競合は不利な結果を考慮し、審判判断まで残る同点は下限・上限を分けます。得点差は勝敗保証を維持する保守的下限です。分類群だけに相手の対抗手を限定しません。

## 検証

```sh
python3 -m unittest discover -s tests -v
cd web
npm test
npm run build
```

現在のモデルは `resource-events-2` です。旧モデルの保存データ・条件JSONとは互換性がありません。旧 `.explorer/` はそのまま残し、新しい保存先で探索を作り直します。

終了までに完了せず、競技物体にも影響しない移動・リトライは待機にまとめます。物体を返すリトライ、取得、反転は開始時点で資源や得点に影響するため、終了時に動作中となる選択も残します。

実作戦を組み、相手の反転を入れて再評価した結果は [実利用レビュー](docs/strategy-use-review-2026-10-13.md) を参照してください。待機の削減によるスペック評価の歪みと、全試合作戦の分類上の問題が確認されています。
